# 软件模拟时序与 GPIO

在嵌入式开发中，I2C（Inter-Integrated Circuit）作为一种经典的串行通信协议，因其引脚占用少（仅需 SDA 和 SCL 两根线）、硬件连接简单、支持多主多从结构而得到了极其广泛的应用。虽然现代微控制器（如 STM32 系列）普遍内置了硬件 I2C 外设，但由于硬件外设内部状态机设计复杂，且早期芯片（如 STM32F103）存在著名的硅片级设计缺陷，在中断嵌套或强电磁干扰环境下极易发生死锁。因此，**通过 GPIO 软件模拟（Bit-Banging）I2C 通信**，成为嵌入式工程师在实际工业和产品开发中首选的健壮通信方案。

本部分将深入探讨如何通过控制 GPIO 模拟出完全符合官方规范的 I2C 物理波形。

---

## 1. I2C 总线物理规范与电平特征

I2C 总线在物理设计上极具艺术性，其核心在于**开漏输出（Open-Drain）**与**线与（Wired-AND）逻辑**的结合：

* **双线结构**：总线由串行时钟线（SCL）与串行数据线（SDA）组成。
* **主动下拉与被动上拉**：总线上所有器件的引脚均需配置为开漏模式。这意味着任何器件都只能主动将总线拉低至地电平（Logic 0），而无法主动驱动总线为高电平。当所有器件都不导通内部 NMOS 时，总线电平由外部上拉电阻（\\(R_{pullup}\\)）拉升至高电平（Logic 1）。
* **物理电平阈值**：标准的 \\(V_{IH}\\)（输入高电平阈值）为 \\(0.7 V_{DD}\\)，\\(V_{IL}\\)（输入低电平阈值）为 \\(0.3 V_{DD}\\)。信号从低变高由于是 RC 充电过程，其上升沿时间受总线寄生电容和上拉电阻大小的限制。

---

## 2. 信号时序与 Start/Stop 条件

标准的 I2C 通信包含以下关键的时序状态：

```
                START 信号                               STOP 信号
      SCL  ______        ______              ______  ______
                 \______/                          \______
      SDA  ________                                  ________
                   \___________                      /
```

* **起始条件 (START)**：在 SCL 保持高电平期间，SDA 发生由高到低的电平跳变。这标志着一次数据传输的开始。
* **停止条件 (STOP)**：在 SCL 保持高电平期间，SDA 发生由低到高的电平跳变。这标志着当前传输的结束，总线释放回空闲状态。
* **数据有效性 (Data Validity)**：在数据传输期间，SDA 的电平在 SCL 为高电平期间必须保持稳定。SDA 的电平改变只能在 SCL 为低电平期间发生。
* **时钟拉伸 (Clock Stretching)**：如果从机处理速度慢于主机的发送速度，从机可以通过强行将 SCL 线拉低来暂停通信，直到其准备完毕释放 SCL，主机检测到 SCL 变高后才能继续。这需要在软件模拟中对 SCL 进行主动读取。

## 3. GPIO 模拟的设计理念

在本章中，我们将深入物理底层，探讨如何在 STM32 平台上高效实现软件模拟：

1. **免方向切换的高效 GPIO 配置**：摒弃传统的频繁读改写模式寄存器来切换 SDA 的输入/输出状态，利用开漏模式下“输出 1 时直接反读输入寄存器”的特性，实现单方向初始化支持双向通信。
2. **高精度微秒级延时**：基于 Cortex-M 内核的 DWT（数据观察点和跟踪）时钟周期计数器实现高精度的时延控制，确保时序在高速/低速下依然严丝合缝。
3. **元动作 API 拆解**：详解 `Start`、`Stop`、`WriteByte`、`ReadByte` 的逐行实现，为后续的防死锁机制和设备驱动编写打下坚实的基石。
