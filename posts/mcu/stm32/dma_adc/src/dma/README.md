# 第二部分：DMA 高速数据搬运 - 引言

当模数转换器（ADC）以数百 kHz 甚至数 MHz 的高采样率运行时，每秒会产生海量的数字化样本。如果由 CPU 通过中断服务程序（ISR）来读取这些数据，高频的现场保护与恢复（上下文切换）将瞬间耗尽 CPU 的主频资源，导致系统陷入“中断风暴”并产生严重的数据丢失或越界错误。

本部分将深入探讨 **STM32 的直接内存访问控制器（DMA）** 及其在高速 ADC 数据流搬运中的高级应用。

---

## 本部分核心主题

### 1. DMA 硬件机制与握手协议
DMA 充当了外设与内存之间数据传输的“旁路硬件协处理器”。我们将揭示其底层的硬件握手机制：当 ADC 转换完成时，如何通过专用信号线（`dma_req`/`dma_ack`）与 DMA 建立连接，由 DMA 直接驱动 AHB/APB 总线读取 ADC 数据寄存器（`ADC_DR`），并自动将其递增写入指定的 SRAM 缓冲区。

### 2. 多层 AHB 总线矩阵与冲突消除（Bus Contention）
微控制器内部的 **多层 AHB 总线矩阵（Multi-Layer Bus Matrix）** 决定了 DMA 与 CPU 是否能同时无阻碍地访问系统资源。当 DMA 试图写入数据，而 CPU 同时也试图读写同一片物理内存区时，总线仲裁器会引入等待周期（Wait States），从而造成总线冲突。我们将剖析如何通过合理的内存映射（如将 DMA 缓冲区放置在独立的物理 SRAM bank、DTCM 或 D2 域 AXI SRAM 中）来实现并发传输，避免传输延迟导致的溢出错误（Overrun）。

### 3. 双缓冲区与循环“乒乓”管理机制
对于持续不断的实时信号流，单缓冲区无法避免 CPU 读与 DMA 写的“竞态条件”（Race Condition）及“数据撕裂”现象。我们将深入探讨如何利用 DMA 的**半传输完成（HT）**和**传输完成（TC）**中断，配合循环模式（Circular Mode），将内存划分为两块互补的半区（Buffer A & Buffer B），以“乒乓”交替读写的方式实现无锁、零拷贝的高速数据闭环管理。

### 4. 高速 Cache 一致性维护（针对 Cortex-M7/M4）
在带有数据缓存（D-Cache）的高性能 MCU（如 STM32H7、F7 等）中，DMA 直接写入 SRAM 的数据无法自动同步到 CPU 的 D-Cache 中，反之亦然。这会导致 CPU 读取到脏数据（Dirty Data）。我们将分析这一机制，并给出通过缓存失效（Invalidate）和内存屏障（DMB/DSB）维护 CPU 与 DMA 数据一致性的权威规范。
