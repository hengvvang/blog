# BLE 协议基础

本部分将深入介绍低功耗蓝牙（Bluetooth Low Energy, BLE）的协议栈核心基础。在真正着手编写 ESP32 的蓝牙代码之前，理解 BLE 的分层架构、链路状态机以及最底层的属性交互协议是至关重要的。

---

## 1. BLE 协议分层架构

BLE 协议栈从物理层至应用层被规范划分为以下三个主体层次：

```
+-------------------------------------------------------+
|                    Application                        |  <-- 用户应用程序与 Profile (如 HID, Heart Rate)
+-------------------------------------------------------+
|                     GAP / GATT                        |  <-- 访问控制与属性数据库层 (Host 内部)
+-------------------------------------------------------+
|                 ATT / SMP / L2CAP                     |  <-- 数据分包、加密安全与属性协议 (Host 核心)
+-------------------------------------------------------+
|                        HCI                            |  <-- 主机控制器接口 (VHCI / 物理串口)
+-------------------------------------------------------+
|                Link Layer (LL) / PHY                  |  <-- 链路状态控制与 RF 物理射频 (Controller)
+-------------------------------------------------------+
```

1. **控制器层 (Controller)：** 
   - **PHY (物理层)：** 负责 2.4GHz 射频信号的收发、GFSK 调制解调，并在 40 个射频信道（37/38/39 为广播信道，0-36 为数据信道）上进行工作。
   - **LL (链路层)：** 处理复杂的射频时序、空中数据包格式定义、CRC 校验、自适应跳频 (AFH) 以及底层的加密重传。
2. **主机层 (Host)：**
   - **L2CAP (逻辑链路控制与适配协议)：** 实现逻辑信道的多路复用、协议数据单元 (PDU) 的分片与重组，是数据从底层向上层传输的“集线器”。
   - **SMP (安全管理协议)：** 提供配对、密钥生成、身份验证和数据加密服务。
   - **ATT (属性协议)：** 属性协议是 BLE 交互的核心，它将设备上的所有状态、传感器数据、控制开关全部抽象为一个个“属性 (Attribute)”，并定义了对其进行读、写、通知的操作指令。
   - **GAP (通用访问配置文件)：** 定义了设备的发现机制、连接建立、广播时序以及角色绑定。
   - **GATT (通用属性配置文件)：** 建立在 ATT 之上，将扁平化的属性结构组织成具有面向对象特征的“服务 (Service)”与“特征 (Characteristic)”层次结构。
3. **应用层 (Application / Profiles)：** 
   - 开发者编写的实际业务逻辑以及 SIG 规范定义的标准 Profile（如电池服务、心率服务、OTA 服务等）。

---

## 2. 链路层 (Link Layer, LL) 角色与状态机

链路层是整个 BLE 控制器最核心的状态转换引擎。它定义了设备在空气中交互的五种核心工作状态：

* **Standby（待机状态）：** 射频模块关闭，不发送也不接收任何无线电信号。
* **Advertising（广播状态）：** 射频模块在特定的广播信道（37、38、39 信道）上周期性发送广播数据包，并短暂监听可能来自主机的扫描请求 (`SCAN_REQ`) 或连接请求 (`CONNECT_IND`)。
* **Scanning（扫描状态）：** 设备处于接收模式，主动监听广播信道上的广播包。
* **Initiating（发起状态）：** 专门监听特定从机设备的广播包。一旦收到符合条件的广播，立即发出连接请求，建立主从关系。
* **Connection（连接状态）：** 双方设备成功建立连接，射频转移到 0-36 号数据信道上通过跳频技术通信。在连接状态下，发起连接的设备成为 **Master (主机 / 发起者)**，发送广播的设备成为 **Slave (从机 / 广播者)**。

---

## 3. 属性协议 (Attribute Protocol, ATT) 核心

ATT 协议是 BLE 协议栈中所有应用层数据传输的物理载体。它采用 **Client/Server（客户端/服务器）** 架构：

* **ATT Server (属性服务器)：** 保存着“属性表 (Attribute Database)”的设备。例如，传感器设备或者带有控制开关的 ESP32，它持有数据并等待被读取或写入。
* **ATT Client (属性客户端)：** 访问 ATT Server 的设备。例如智能手机，它向 Server 发起读、写、订阅等请求。

### 属性 (Attribute) 的四个基本属性

在属性数据库中，每一个条目（不管是服务、特征还是描述符）都是一个 `Attribute`，它在内存中由以下四个字段唯一标识：

```
+---------------------------------------------------------------------------------+
| Attribute Handle (句柄) | Attribute UUID (类型) | Value (值) | Permissions (权限) |
+---------------------------------------------------------------------------------+
```

1. **Attribute Handle (属性句柄)：** 属性在数据库中的 16 位地址索引（0x0001 ~ 0xFFFF）。Client 必须通过句柄来精确定位和操作具体的属性。
2. **Attribute UUID (通用唯一识别码)：** 标识该属性的“类型”。例如，`0x2800` 代表这是一个“主要服务 (Primary Service)”，`0x2803` 代表这是一个“特征声明 (Characteristic Declaration)”，`0x2902` 代表这是一个“客户端特征配置描述符 (CCCD)”。
3. **Value (值)：** 属性所携带的实际数据。对于特征声明，其 Value 包含特征的读写性质及特征值的 UUID；对于真实的特征值，其 Value 就是具体的业务数据（如温度、开关状态）；对于 CCCD，其 Value 就是一个 2 字节的使能位。
4. **Permissions (权限)：** 规定了 Client 对该属性的访问级别，包括是否可读（Read）、可写（Write）、是否需要加密链路（Encryption Required）或配对授权（Authentication Required）。
