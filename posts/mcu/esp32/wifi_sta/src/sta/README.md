# 第二部分：连接管理与事件驱动机制

本部分将深入探讨 ESP32 在 Wi-Fi 站模式（STA 模式）下的连接管理架构与状态自愈（Self-Healing）重连机制。

在真实的物理部署环境中，无线连接是动态且不可靠的。路由器重启、强电磁干扰或设备物理移动都会导致连接丢失。要开发出工业级和消费级高稳定性的嵌入式物联网系统，必须依赖一套清晰、健壮的**状态机**和基于**异步事件循环**的驱动架构。

---

## 1. 核心技术组件

要实现高抗干扰性、高稳定性的网络连接层，必须掌握以下三个核心技术组件：

```
                             +-----------------------+
                             |   事件驱动回调注册    |
                             | (WIFI_EVENT / IP_EVENT)
                             +-----------------------+
                                         |
                                         v [接收异步通知]
+-----------------------+    +-----------------------+    +-----------------------+
| 指数退避重连算法        | <-- | 状态自愈管理任务       | --> | 线程安全同步机制       |
| (Exponential Backoff) |     | (有限状态机守护线程)   |     | (FreeRTOS 事件组/锁)  |
+-----------------------+    +-----------------------+    +-----------------------+
```

1.  **事件驱动机制 (esp_event)**：
    *   Wi-Fi 底层驱动和 LwIP 协议栈运行在独立的高优先级任务中，状态改变时会异步向系统队列投递事件。
    *   通过注册回调函数（Event Handler）订阅对应事件。**本章将重点强调“回调函数严禁阻塞”的底层核心原因。**
2.  **有限状态机 (FSM) 架构**：
    *   将 Wi-Fi 从初始化、正在关联、等待分配 IP、成功连接以及断开退避等全过程，设计为五个排他的清晰状态。
    *   定义了在各种异常事件触发下，状态发生安全跳转的转移链路，杜绝死锁与无解的中间态。
3.  **指数退避与随机抖动重连算法 (Exponential Backoff with Jitter)**：
    *   为了防止设备在信号丢失或路由器关机时发起死循环重连，我们引入了指数退避时间计算法。
    *   为了避免数十台设备在停电重启后同时重连造成路由器崩溃（重连风暴），重连等待时间加入了硬件随机数抖动（Jitter）。
