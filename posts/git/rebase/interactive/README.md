# Git Rebase 交互式变基精讲

在团队协作开发中，杂乱无章的 Git 提交历史会大大增加代码审查与回滚的难度。利用 `git rebase -i` 交互式变基操作，我们可以在将分支合并到主干前，对本地多次琐碎的提交进行整理、合并与重构，从而维护一条干净漂亮的“单线型”提交日志。

## 什么是交互式变基？

通常，变基是将一个分支的修改重新应用到另一个分支的顶端。而交互式变基（Interactive Rebase）则允许你在应用修改的过程中暂停，交互式地选择如何处理每一个提交。

你可以运行以下命令对最近的 4 次提交进行整理：

```bash
git rebase -i HEAD~4
```

输入后，Git 会调出系统默认编辑器，显示类似于下方的文本：

```text
pick a1b2c3d 增加用户登录界面
pick d4e5f6g 修复拼写错误
pick h7i8j9k 编写登录接口单元测试
pick l0m1n2o 优化文档

# 变基指令说明:
# p, pick = 保留该提交
# r, reword = 保留提交，但修改提交信息
# e, edit = 暂停处理以修改内容（如添加文件、分拆提交等）
# s, squash = 合并提交到前一个提交，并合并提交信息
# f, fixup = 类似于 squash，但丢弃当前提交的日志信息
# d, drop = 彻底丢弃该提交
```

## 常用操作实践

### 1. 合并多个琐碎的 WIP 提交 (Squash / Fixup)

在开发新功能时，我们常会有许多类似 "WIP"、"fix typo" 的临时提交。合并它们：

```text
pick a1b2c3d 增加用户登录界面
fixup d4e5f6g 修复拼写错误
pick h7i8j9k 编写登录接口单元测试
fixup l0m1n2o 优化文档
```

保存并退出编辑器后，Git 会自动将第 2 次合并到第 1 次中，第 4 次合并到第 3 次中，最终只留下两个清晰的逻辑提交。

### 2. 修改历史提交信息 (Reword)

如果发现早先提交的日志不规范，只需将前面的 `pick` 改为 `reword` 即可：

```text
reword a1b2c3d 增加用户登录界面
pick h7i8j9k 编写登录接口单元测试
```

退出后，Git 会再次打开编辑器让你修改 `a1b2c3d` 的日志内容。

## 变基黄金法则

> [!WARNING]
> **绝对不要在公共共享分支上执行 Rebase 变基！**
> 变基会重写提交的 SHA-1 哈希值。如果你重写了已经推送到公共服务器上的提交，会导致其他同事拉取时产生大量的合并冲突和重复历史。变基只适合用在推送到远端之前的**本地个人开发分支**上。

## 总结

学会 `git rebase -i` 可以让你的工作流提升一个档次，每次合并 PR 时都能给团队展现一条逻辑连贯、主线分明的提交脉络，让 Code Review 变得轻松愉快。
