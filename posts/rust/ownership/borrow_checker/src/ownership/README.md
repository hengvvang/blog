# 所有权与借用

欢迎来到本书的第一部分。在这一部分中，我们将深入探讨 Rust 赖以生存的核心内存安全机制：**所有权模型**与**借用规则**。通过静态编译期的严苛检查，Rust 实现了无垃圾回收（Garbage Collection）的确定性资源管理与并发安全。

为了奠定扎实的理论与实践根基，我们将在这部分中重点解构以下五大支柱概念：

## 1. 资源获取即初始化 (RAII)
Rust 继承并拓展了系统级编程中经典的 **RAII (Resource Acquisition Is Initialization)** 机制。在 Rust 中，任何资源（无论是堆内存、文件描述符、网络套接字还是互斥锁）都被严密地封装在某个类型实例（所有者变量）之中。
- **绑定即获取**：资源的生命周期自其绑定到变量的那一刻开始。
- **离开即释放**：当变量超出其有效作用域时，编译器会在该处自动、静态地插入对应的 `Drop` 析构调用，完成资源的确定性回收，彻底杜绝内存泄漏和野指针。

## 2. 所有权三大核心规则 (Ownership Rules)
所有权模型是一套用于管理程序内存的规则系统。它的核心规律可以概括为以下三条：
1. **唯一所有权**：Rust 中的每个值都有一个被称为其**所有者**（Owner）的变量。
2. **单主制**：同一时间，任何值都只能有且仅有一个所有者。
3. **自动释放**：当所有者离开作用域时，该值将被丢弃并自动释放其持有的所有资源。

## 3. 移动 (Move) 与 复制 (Copy) 语义
当进行变量赋值、传参或从函数返回时，Rust 在语义层面会对值的流转进行严格界定：
- **移动语义 (Move Semantics)**：适用于默认的大多数类型。赋值或传参时，在底层只进行简单的栈上固定大小元数据拷贝（如指针、长度和容量，即 `memcpy`），但编译器会使得原变量失效（Moved state）。这确保了堆内存资源不会发生多重释放。
- **复制语义 (Copy Semantics)**：如果类型实现了 `Copy` trait（通常是栈上具有固定大小的简单标量类型或完全由其组成的复合结构），则在赋值时执行隐式的按位复制（Bitwise Copy），原变量和新变量均保持有效。

## 4. 别名与可变性限制 (Aliasing Limits)
为了防范多线程下的“数据竞争”（Data Race）以及单线程下的“迭代器失效”（Iterator Invalidation），Rust 确立了**别名与可变性互斥**原则（Aliasing XOR Mutability）：
- **共享不可变**：你可以拥有任意数量的只读引用（`&T`）。
- **可变不共享**：你只能拥有一个活跃的可变引用（`&mut T`），并且在此期间无法拥有该值的其他只读引用或可变引用。

## 5. 词法生命周期 (LL) 与非词法生命周期 (NLL)
生命周期是编译器借用检查器用来描述一个借用（引用）合法存活的代码区间：
- **词法生命周期 (Lexical Lifetimes, LL)**：旧版本 Rust 采用基于语法大括号层级的生命周期判断，极易误判安全的流转逻辑。
- **非词法生命周期 (Non-Lexical Lifetimes, NLL)**：现代 Rust 引入了基于控制流图 (CFG) 的活性分析。编译器可以精确追踪引用在图上的具体使用痕迹，在引用实际不再使用（Dead）时立即释放借用限制，从而大幅提升了编写 Rust 时的流畅度。
