# 第一部分：子类型、型变与高阶生命周期

在 Rust 中，生命周期不仅是一个简单的“作用域范围”概念，更是类型系统（Type System）中用于支撑安全借用推导的重要维度。为了能够设计出高度灵活且绝对安全的泛型库，我们必须首先掌握类型系统在生命周期维度上的代数运算——**子类型关系**与**型变特征**，以及用于约束泛化生命周期的**高阶生命周期限制 (HRTB)**。

## 本部分核心主题

本部分将分为两个章节，深入剖析以下核心概念：

1. **子类型关系 (Subtyping)**
   - 虽然 Rust 没有传统的面向对象类继承，但生命周期本身存在子类型关系。
   - 当 `'a` 的生命周期长于（或等于）`'b` 时（记作 `'a: 'b`），意味着 `'a` 是 `'b` 的子类型（记作 `'a <: 'b`），因为长生命周期的引用在任何需要短生命周期引用的地方都是安全可用的。

2. **型变 (Variance)**
   - 型变探讨的是：当泛型参数 `T` 具有子类型关系时，复合类型 `F<T>`（如 `&'a T`、`&'a mut T`、`fn(T)` 等）是否以及如何继承这种子类型关系。
   - **协变 (Covariance)**：子类型方向保持一致。若 `T <: U`，则 `F<T> <: F<U>`。
   - **逆变 (Contravariance)**：子类型方向反转。若 `T <: U`，则 `F<U> <: F<T>`。
   - **不变 (Invariance)**：子类型关系失效，必须完全一致。即便 `T <: U`，`F<T>` 与 `F<U>` 之间也无子类型关系。

3. **高阶生命周期约束 (HRTB - Higher-Rank Trait Bounds)**
   - 当我们需要编写接收闭包作为参数的泛型函数，且闭包的参数生命周期无法由调用者提前指明（例如由函数内部临时创建的局部引用的生命周期），我们就需要使用 `for<'a>` 语法。
   - HRTB 允许我们表达“该闭包对任意生命周期参数 `'a` 都满足特定边界约束”的属性。
