# Rust Tokio 异步运行时与任务调度

欢迎阅读《Rust Tokio Async Runtime & Scheduling》。本书旨在为你剖析 Rust 异步生态的事实标准 —— **Tokio 运行时**的底层设计与实现机制。

## 为什么需要这本书？

Rust 的异步编程模型在系统级编程语言中独树一帜。它采用了**基于 Poll（拉取式）**的惰性 Future 状态机模型，而非传统语言（如 Go、Erlang）的基于 Push（推送式）的 runtime-managed 协程模型。这种设计带来了极致的性能和零开销抽象的可能性，但也将极大的设计复杂度留给了**运行时（Runtime）**。

在 Rust 的异步世界中，标准库仅提供了底层的异步语义核心（如 `Future` trait、`Pin`、`Context` 和 `Waker`），而没有内置任何具体的事件循环、任务调度器或异步 I/O 驱动。所有这些职责都由第三方运行时库承担。**Tokio** 正是其中最成熟、最通用、性能最强悍的高并发异步运行时。

然而，在实际开发和生产运维中，许多开发者仅将 Tokio 视为一组 `#[tokio::main]` 宏和 `async/await` 的语法糖。当面临如下生产级别的复杂问题时，往往会感到无从下手：
1. **CPU 密集型任务阻塞了异步线程池**，导致其他异步 I/O 任务发生严重的延迟抖动；
2. **多线程调度下的 Work-Stealing（工作窃取）**是如何在局部队列与全局队列之间平衡负载的？
3. **协作式调度（Cooperative Scheduling）**是如何通过任务预算（Budget）防止饥饿的？
4. **异步通道（Channels）与同步锁（Mutex）**在底层是如何与 Waker 和运行时唤醒器深度集成的？

为了彻底解开这些谜团，本书将抛开浅层的 API 教学，带你深入 Tokio 的源码级设计，探索高性能异步运行时的工程实现哲学。

## 本书内容大纲

本书共分为三个核心章节，环环相扣，由浅入深地带你重构对异步运行时的认知：

### [第一章：Tokio 运行时架构深度解析](01_tokio_architecture.md)
* **核心组件剖析**：理解 Driver（驱动层，包括 I/O、Timer）、Scheduler（调度层，包括多线程与单线程模式）的拓扑关系。
* **MIO 与操作系统事件循环**：深入操作系统内核（Linux `epoll` / Windows `IOCP` / macOS `kqueue`），阐明底层事件如何一步步向上抽象并转换为 `Waker` 的唤醒信号。
* **运行时的双面性**：对比 `current_thread` 与 `multi_thread` 的适用场景与内存模型差异。

### [第二章：异步任务执行与工作窃取调度机制](02_async_tasks_execution.md)
* **Tokio 调度器内存布局**：剖析多线程模式下的本地队列（Local Queue，无锁环形缓冲区）与全局队列（Global Queue）的设计。
* **工作窃取（Work-Stealing）算法**：通过详尽的图解与代码还原，展示空闲 Worker 线程如何窃取其他线程的本地队列任务。
* **协作式限制（Budget System）**：讲解 Tokio 1.0 引入的 Task Budget 机制，防止热循环（Hot Loops）导致其他 Future 饿死。
* **LIFO Slot 机制**：揭秘最近运行任务的快速缓存通道，实现极致的缓存局部性。

### [第三章：异步同步原语与通道设计](03_async_synchronization.md)
* **异步锁与通道的本质**：解释为什么在异步上下文中**绝不能**使用标准库 `std::sync::Mutex`，以及异步 `tokio::sync::Mutex` 如何在等待锁时不阻塞操作系统线程。
* **四大通道（Channels）深度对比**：分析 `mpsc`（多生产者单消费者）、`broadcast`（多生产者多消费者）、`watch`（单生产者多消费者状态广播）、`oneshot`（单次通信）的内部状态机设计。
* **零拷贝与唤醒优化**：结合 Rust 代码实例，探讨如何优雅地利用同步原语设计高性能、无阻塞的生产级后台任务系统。

## 学习目标

阅读完本书后，你将能够：
* 深刻理解 Rust 异步 Future 在被 Poll 时的状态扭转与内存布局；
* 根据业务特性（CPU 密集型 vs. I/O 密集型）调优 Tokio 运行时的核心参数；
* 掌握无锁队列（Lock-free Queue）在多核调度器中的实际工程实践；
* 规避异步代码中的各种死锁、假死与性能衰退陷阱，编写出高吞吐、低延迟的 Rust 系统级程序。
