# 第一部分：操作系统线程管理与编译期安全

在本部分中，我们将深入探讨 Rust 多线程并发的核心控制层与安全防御层。与大多数依赖运行时虚拟机或解释器的语言不同，Rust 采用的是直接映射到操作系统内核的 **1:1 物理线程模型**。这种模型能够让多线程程序充分榨干硬件处理器的多核并发性能，但也带来了线程生存期管理与跨线程数据流转的安全难题。

为了在没有任何运行时性能损耗的前提下解决这些难题，Rust 的类型系统在编译期设立了坚实的静态安全防线。

---

## 本部分核心技术专题

本部分分为两个章节，由浅入深地剖析多线程并发的物理基础和安全机制：

### 1. [第一章：OS 线程创建、生命周期与 Scope 线程机制](thread-management.md)
* **1:1 物理线程模型**：解构 Rust 线程与操作系统内核线程的映射逻辑，剖析系统调用与线程栈内存的分配策略。
* **`std::thread::spawn` 的局限性与 `'static` 约束**：从内存空间的角度解析为什么子线程的生命周期必须独立于父线程，以及如何利用 `move` 闭包转移所有权以规避悬垂指针风险。
* **作用域线程（Scoped Threads）**：深入分析 Rust 1.63 引入的 `std::thread::scope` 机制，了解它是如何通过在作用域结束时强制执行 `join` 来确保生命周期安全，从而实现在无需 `Arc` 或拷贝的情况并发借用栈上可变/不可变局部变量。
* **线程定制与异常管理**：使用 `std::thread::Builder` 定制线程的栈大小与名称，并研究子线程中 panic 发生时的堆栈展开（Unwinding）与异常向主线程传播的机制。

### 2. [第二章：编译期并发安全保障与 Send/Sync 特征原理](send-sync-safety.md)
* **标记特征（Marker Traits）的编译器原理**：理解 `Send` 与 `Sync` 的定义、内在数学关联以及编译器是如何通过自动派生特征（Auto Traits）静态分析所有类型成员的。
* **经典单线程类型在多线程下的崩溃推导**：
  * 深度拆解 `Rc<T>` 的引用计数机制，剖析非原子自增/自减操作在多线程下由于数据竞争引发的内存泄漏与释放后使用（UAF）漏洞。
  * 拆解 `RefCell<T>` 的内部可变性计数器，推导并发状态下同时获取多个可变引用（`&mut T`）是如何突破借用检查器防线的。
* **`Arc<T>` 与 `Mutex<T>` 的内存布局与同步机制**：结合详细的内存映射图，直观展现多线程共享指针、堆上 `ArcBox` 原子计数器、互斥锁（Mutex）保护下的临界区数据流转。分析锁毒化（Lock Poisoning）及其在生产环境中的安全检测与恢复策略。

## 物理内存模型与并发安全边界

在多线程环境下，每个线程都有自己独立的**程序计数器（PC）**和**调用栈（Stack Frame）**，但是它们共享同一个进程的**虚拟地址空间（Heap, Data, Text 字段）**。

```
+-------------------------------------------------------------+
|                        操作系统进程                         |
|                                                             |
|  +--------------------+             +--------------------+  |
|  |     线程 1 栈帧    |             |     线程 2 栈帧    |  |
|  |  [局部变量 / 指针] |             |  [局部变量 / 指针] |  |
|  +---------+----------+             +---------+----------+  |
|            |                                  |             |
|            |             共享虚拟内存          |             |
|            +------------> [ 堆 (Heap) ] <-----+             |
|                           [全局静态区]                      |
|                                                             |
+-------------------------------------------------------------+
```

Rust 的并发安全模型正是基于此物理划分进行构建的：
* **栈上数据安全**：利用编译期生命周期（Lifetimes）与借用检查，防止线程 1 借用线程 2 栈上已经被释放的局部变量。
* **堆上共享安全**：利用 `Send` / `Sync` 类型约束和 `Arc` / `Mutex` / `RwLock` 等多线程安全原语，保证跨栈帧传递的堆上指针在并发读写时，能够严格通过原子指令和操作系统互斥锁进行同步，消灭数据竞争。
