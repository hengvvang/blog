# 第一部分：任务调度与堆栈布局

实时操作系统的基石在于任务调度与执行现场的保存。本部分聚焦于任务在内存中的静态数据表示（任务控制块 TCB）以及任务运行时的隔离空间（任务栈）。

在多任务并发的实时系统设计中，内核如何知道一个任务当前运行到哪里？它的局部变量保存在何处？它是否处于就绪状态？为了回答这些问题，我们将详细拆解以下几个核心概念：

### 1. 任务控制块 (Task Control Block, TCB)
TCB 是任务在操作系统内核中的“身份证”和实体代表。每个任务都有其独立的 TCB 实例，记录了任务当前的栈顶指针、任务的状态、优先级、拥有的资源（如持有的互斥锁数量）以及调试信息。它是操作系统调度器进行决策的主要数据来源。

### 2. 双堆栈机制 (Dual Stack Mechanism)
在裸机系统开发中，往往只有一个堆栈，所有的局部变量、函数嵌套调用以及中断处理程序都共用这个栈空间。而在 Cortex-M 架构的 RTOS 中，为提升系统的安全性和执行效率，引入了双堆栈机制：
*   **主堆栈指针 (MSP)**：供内核自身运行、中断服务程序 (ISR) 运行；
*   **进程堆栈指针 (PSP)**：供各个用户任务运行。每个任务在各自的 PSP 空间中运行，彼此独立。

### 3. 任务堆栈分配方案
FreeRTOS 支持动态与静态的堆栈分配：
*   **动态分配 (`xTaskCreate`)**：由内核从 RTOS 堆中自动切出一块内存用于存放 TCB 和任务栈，使用方便，但存在内存碎片的风险。
*   **静态分配 (`xTaskCreateStatic`)**：由用户提供编译时分配好的 TCB 结构体和任务栈数组，适用于对内存安全性有严苛要求、禁止动态内存分配的硬实时嵌入式系统。
