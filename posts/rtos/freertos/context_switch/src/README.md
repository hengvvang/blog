# 引言：嵌入式操作系统的低级别基石

在现代嵌入式系统开发中，实时操作系统（RTOS）为多任务并发执行提供了核心支持。为了在单核或多核处理器上模拟出多个任务同时运行的假象，内核必须频繁、快速且安全地在不同的代码执行流之间进行切换。这一过程被称为**任务上下文切换（Context Switch）**。

对于嵌入式系统工程师而言，仅仅了解高层的 RTOS API 是远远不够的。当系统面临硬实时性（Hard Real-Time）要求、栈溢出（Stack Overflow）、诡异的死机（HardFault）或者由于资源竞争导致的系统响应迟钝时，只有深入理解底层寄存器操作、汇编级的上下文恢复细节，以及微控制器的硬件中断架构，才能进行精准的调试与系统优化。

本书将以 **ARM Cortex-M** 架构与 **FreeRTOS** 内核为核心，层层剥离底层汇编代码，深入探讨任务调度、上下文切换的硬件基础与软件实现，并系统性地分析多任务同步中最为经典的问题——**优先级翻转（Priority Inversion）**及其解决方法。

## 核心技术脉络

### 1. 任务控制块（TCB）与堆栈双重奏
在 FreeRTOS 中，每个任务都由一个任务控制块（Task Control Block, TCB）来描述。TCB 记录了任务的当前状态、优先级、以及至关重要的**栈顶指针（`pxTopOfStack`）**。
Cortex-M 处理器具备独特的**双堆栈机制（MSP & PSP）**：
*   **主堆栈指针（Main Stack Pointer, MSP）**：专用于处理中断服务程序（ISR）以及内核自身的运行，保证了中断处理的快速与安全。
*   **进程堆栈指针（Process Stack Pointer, PSP）**：专用于运行用户任务，使得每个任务都有其独立的栈空间，避免了任务间的栈空间污染。

上下文切换的本质，就是在硬件和软件的协同下，将当前任务的 CPU 寄存器状态保存到其对应的 PSP 堆栈中，并将下一个就绪任务先前保存的寄存器状态从其 PSP 堆栈中恢复到 CPU 寄存器中，最后切换 PSP 指向的过程。

### 2. PendSV 与硬件调度机制
传统的操作系统可能直接在定时器中断（如 SysTick）中执行上下文切换。然而，在 Cortex-M 等现代微控制器中，这种做法会导致**中断延迟**和**中断嵌套异常**。
为解决此问题，ARM 引入了 **PendSV（Pending Supervisor Call，可悬起系统调用）** 中断。
*   **SysTick 中断**只负责周期性地触发，决定是否需要调度。如果需要，它会向中断控制寄存器写入特定位，悬起（Pending）一个最低优先级的 PendSV 中断。
*   **PendSV 中断**由于被设置为最低优先级，它会等待所有其他高优先级的中断服务程序（ISR）执行完毕后，在没有任何中断嵌套的时刻安全地触发。
*   在 PendSV 的中断服务程序中，通过纯汇编代码完成通用寄存器（R4-R11）及浮点寄存器（S16-S31）的保存与恢复，实现无缝的任务切换。

### 3. 优先级翻转与互斥锁的自愈机制
多任务系统不可避免地要共享临界资源（如串口、I2C 总线、共享内存）。当高优先级任务等待低优先级任务释放资源，而中等优先级任务又抢占了低优先级任务时，就会发生灾难性的**优先级翻转**——高优先级任务被无限期阻塞，中等优先级的任务反而优先运行。
本书将结合 FreeRTOS 的源码分析：
*   **二值信号量（Binary Semaphore）** 为什么无法预防优先级翻转。
*   **互斥锁（Mutex）** 如何通过**优先级继承协议（Priority Inheritance Protocol）**，在检测到高优先级任务阻塞时，动态提升持有锁的低优先级任务的优先级，使其快速运行并释放锁，最后恢复原优先级，从而完美解决这一经典隐患。
