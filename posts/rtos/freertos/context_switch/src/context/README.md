# 第二部分：上下文切换底层实现

本部分深入探讨微控制器架构底层的核心机制：**任务上下文切换 (Context Switch)**。

在多任务并发执行的 RTOS 中，当一个任务的时间片用完，或者因为等待某些事件而主动让出 CPU 时，内核需要将当前任务的 CPU 现场（即所有寄存器的状态）完整保存到内存中，并将新任务的现场加载回 CPU。这一过程必须以极高的效率和极强的稳定性运行。

在本部分中，我们将围绕以下核心议题展开讨论：

### 1. 硬件异常压栈 (Hardware Exception Stacking)
当微控制器检测到异常或中断信号（如 SysTick、外部 GPIO 中断等）时，硬件自动开启的压栈流程。我们将深入理解这种硬件层面的微码级操作，它如何与 C 语言调用约定（AAPCS）无缝契合，以及它是如何通过 PSP 和 MSP 两个指针进行堆栈分流的。

### 2. PendSV 中断与延迟调度
传统的 RTOS 可能会在定时器中断中强行执行任务切换，但这在 Cortex-M 的中断嵌套（Interrupt Nesting）环境下会导致严重的系统崩溃或高实时性中断的延迟。PendSV（可悬起系统调用）以其最低优先级的配置、可手动悬起的特性，成为承载上下文切换的最佳载体。

### 3. 汇编级上下文恢复与 EXC_RETURN
在任务被切换回来时，CPU 如何通过特殊的 `EXC_RETURN` 机制退出 Handler 模式并重置控制寄存器（CONTROL），从而实现平滑过渡？我们将通过汇编指令剖析现场的恢复过程。
