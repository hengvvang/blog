# 第二部分：栈溢出检测与内存泄漏调试

如果说第一部分的“栈水位分析”是防患于未然的“预防性监视”，那么当系统由于不可预测的运行时异常发生内存损坏时，我们就必须依赖坚固的**运行时防御系统**和**动态调试机制**。

在缺少现代操作系统（如 Linux 或 macOS）虚拟地址空间保护的微控制器上，任何微小的内存越界都可能是致命的。常见的内存故障包括：
*   **栈物理溢出（Stack Overflow）**：执行流越过了栈底物理线，踩坏了其他关键变量。
*   **动态堆泄漏（Heap Leak）**：`malloc`/`free` 不配对，导致物理 RAM 不断丢失，最终引发内存耗尽（OOM）。

## 核心防御与调试机制

本部分将带您深入 Zephyr 最底层，探讨两类关键的防御与定位技术：

### 1. 硬件级与软件级栈溢出检测
*   **基于 MPU 的物理屏障**：在栈的底部强行布置一块禁写区（Guard Page）。一旦有越界行为，立即由硬件捕获并抛出 MemManage Fault，实现零延时的故障锁定。
*   **基于硬件限制寄存器（PSPLIM）的防御**：在 ARMv8-M 等新型架构下，直接使用硬件比较寄存器限制进程栈指针 `SP` 的边界，零碎片开销实现防护。
*   **基于软件金丝雀（Canary）的巡检**：在每次任务上下文切换时校验特定魔术字，为不支持 MPU 的低端 MCU 提供安全防护。

### 2. 系统堆内存泄漏诊断
*   **运行时分配状态统计**：实时掌握系统堆的空闲字节、已分配字节和历史峰值。
*   **堆分配追踪器（Heap Alloc Tracker）**：通过在开发调试阶段重定向 `k_malloc`/`k_free` 接口，追踪所有当前处于活动状态（未被释放）的内存块，记录分配时的文件名、行号以及时间戳，精准还原“内存是谁在什么时候分配的”。

## 本部分学习重点

1.  **深入理解异常寄存器**：学会分析 `CFSR`、`MMFAR`、`PSP`、`MSP`，在 HardFault 发生的瞬间精确定位出越界地址和故障原因。
2.  **中断栈（ISR Stack）管理**：掌握中断嵌套引发的 MSP 栈溢出排查与防范原则。
3.  **自研 Heap Tracker**：在不依赖任何第三方调试工具的前提下，掌握编写轻量级内存泄漏检测引擎的架构设计。
