# 第二章：表格对齐、特殊字符与文字排版标准

技术文档的阅读体验在很大程度上取决于字符之间的微观排版。中文与西文字符在字形设计、字宽、基线位置上存在显著差异。本章将详细规范中西文混排空格（盘古之白）、标点符号映射、专业术语拼写以及代码与公式混排的标准。

---

## 1. 中西文混排空格规范 (盤古之白)

在中文段落中混排英文单词、数字、数学符号或技术专有名词时，字符间的过度拥挤会严重降低阅读流畅度。因此，必须在中文与西文/数字之间插入**一个半角空格**，通常这被称为“盘古之白”。

### 1.1 必须使用空格的场景

*   **汉字与英文单词/短语之间**：
    ```markdown
    <!-- 正确示例 -->
    我们在本项目中采用 Rust 语言进行底层驱动开发。

    <!-- 错误示例 -->
    我们在本项目中采用Rust语言进行底层驱动开发。
    ```
*   **汉字与阿拉伯数字之间**：
    ```markdown
    <!-- 正确示例 -->
    该 MCU 芯片在 168 MHz 主频下工作稳定。

    <!-- 错误示例 -->
    该MCU芯片在168MHz主频下工作稳定。
    ```
*   **汉字与行内代码块之间**：行内代码块在视觉上等同于英文单词，必须在其左右两侧添加空格。
    ```markdown
    <!-- 正确示例 -->
    调用 `sys_init()` 函数前必须先使能外设时钟。

    <!-- 错误示例 -->
    调用`sys_init()`函数前必须先使能外设时钟。
    ```
*   **汉字与行内数学公式之间**：
    ```markdown
    <!-- 正确示例 -->
    当系统的信噪比 $SNR$ 降低时，误码率会显著上升。
    ```

### 1.2 禁用空格的场景

为了避免排版过于松散、零碎，以下场景**严禁插入空格**：

*   **英文、数字紧邻中文全角标点符号时**：全角标点符号（如逗号、句号、冒号、括号等）自身已经带有足够的视觉空白，此时绝对不能再插入空格。
    ```markdown
    <!-- 正确示例 -->
    推荐使用 Git，因为它是目前最流行的分布式版本控制系统。
    这是由 ST 生产的微控制器（MCU）。

    <!-- 错误示例：全角标点符号前后加了冗余空格 -->
    推荐使用 Git ，因为它是目前最流行的分布式版本控制系统。
    这是由 ST 生产的微控制器（ MCU ）。
    ```
*   **数字与百分号 `%` 或度数符号 `°C` 相邻时**：
    ```markdown
    <!-- 正确示例 -->
    系统 CPU 占用率已达到 95%。
    芯片的极限工作温度为 -40°C 至 125°C。

    <!-- 错误示例 -->
    系统 CPU 占用率已达到 95 %。
    芯片的极限工作温度为 125 °C。
    ```
*   **技术术语内部的斜杠或特定符号**：
    ```markdown
    <!-- 正确示例 -->
    采用 TCP/IP 协议族进行以太网通信。
    设计中包含了 I2C/SPI 双总线接口。

    <!-- 错误示例 -->
    采用 TCP / IP 协议族进行以太网通信。
    ```

## 2. 标点符号规范 (Punctuation Standards)

标点符号在排版中具有指示语法停顿和句法结构的重要功能。中英文标点的随意混用是技术文档中最常见、也最影响专业度的硬伤。

### 2.1 全角与半角的选用原则

*   **中文段落内**：必须使用**全角（中文）标点符号**。包括：`，` `。` `、` `；` `：` `？` `！` `（` `）` `《` `》` `“` `”` `——` `……`。
*   **英文段落或代码块内**：必须使用**半角（英文）标点符号**。包括：`,` `.` `;` `:` `?` `!` `(` `)` `"` `'` `-` `...`。
*   **括号的匹配（非常重要）**：如果整句话是中文，即使括号内是纯英文或数字，也必须使用**中文全角括号**：
    ```markdown
    <!-- 正确示例：中文句子中使用中文括号 -->
    微控制器（如 STM32F407）提供了丰富的定时器资源。

    <!-- 错误示例：中文句子中混入英文括号 -->
    微控制器 (如 STM32F407) 提供了丰富的定时器资源。
    ```

### 2.2 重点标点符号的使用规范

| 标点符号 | 正确符号 | 键盘输入说明 | 使用规范说明 |
| :--- | :---: | :--- | :--- |
| **省略号** | `……` | `Shift + 6` (中文输入法) | 必须是两个全角字符（共 6 个点），禁止使用英文 `...` 或堆叠多个 `......`。 |
| **破折号** | `——` | `Shift + -` (中文输入法) | 必须是两个全角字符，占两格宽度，中间不能有缝隙。 |
| **书名号** | `《 》` | `<` 和 `>` (中文输入法) | 用于书名、篇名、规范标准名、软件库名或框架名，如《C 程序设计语言》、《RFC 2616》。 |
| **连接号** | `—` 或 `～` | `Shift + -` 或 `Shift + ~` | 表示数值范围、起止时间时，推荐使用波浪号 `～`，例如：`10～20 MHz`。 |

## 3. 技术缩写与专有名词大小写

技术拼写错误和大小写不一致会严重损害文档的专业度。所有技术品牌、库、协议、语言名称必须遵循其官方定义的大小写格式。

### 3.1 常见专有名词拼写规范表

| 规范拼写 (Correct) | 常见错误拼写 (Incorrect) | 备注说明 |
| :--- | :--- | :--- |
| **Git** | git, GIT | 作为版本控制工具名时首字母大写 |
| **GitHub** | Github, github | H 必须大写 |
| **macOS** | MacOS, macos, Mac OS | 苹果操作系统标准写法 |
| **JavaScript** | Javascript, javascript | S 必须大写，简称 JS 全大写 |
| **JSON** | Json, json | 缩写词，必须全大写 |
| **HTML** / **CSS** | html / css | 网页技术标准缩写，必须全大写 |
| **mdBook** | mdbook, MDBook | 编译引擎名，B 必须大写 |
| **CMake** | Cmake, cmake | 构建工具标准写法 |
| **Python** | python, PYTHON | 开发语言名首字母大写 |
| **Docker** | docker, DOCKER | 容器化引擎首字母大写 |
| **FreeRTOS** | freertos, FreeRtos | 开源嵌入式实时操作系统标准写法 |
| **Cortex-M** | cortex-m, Cortex M | ARM 微控制器架构标准写法 |
| **ESP32** | esp32, Esp32 | 乐鑫微控制器型号标准写法 |

> [!NOTE]
> 当拼写作为命令行工具或代码变量出现时，应使用行内代码块包裹，并保持命令的原生写法。例如：`使用 git commit 提交代码`。

## 4. 代码与公式混排规范 (Typography for Code and Math)

代码和公式通常有独立的字体和行高设置，混排不当会导致行距参差不齐。

### 4.1 行内代码排版

*   行内代码应只包裹**纯粹的代码段、路径、文件名、变量名或命令行**。
*   不要将普通的英文翻译或强调短语放入行内代码，这会污染 AST 的 `CodeSpan` 属性并导致视觉断裂。
    ```markdown
    <!-- 正确示例 -->
    通过编辑 `/etc/hosts` 文件来映射本地 IP 映射关系。

    <!-- 错误示例：过度滥用 inline code 标记普通英文单词 -->
    这个系统运行得非常 `fast` 并且具有很高的 `stability`。
    ```

### 4.2 数学公式排版

*   **行内公式**：使用单个 `$` 包裹（如 $E = mc^2$），公式与中文之间同样需要保留一个半角空格。
*   **块级公式**：使用双 `$$` 包裹，且公式必须单独成行。
    $$ f(x) = \int_{-\infty}^{\infty} \hat{f}(\xi) e^{2 \pi i x \xi} d\xi $$
*   公式内部的变量若在正文中提及，也必须使用行内公式或斜体标注，以保持字体一致性（如“变量 $x$ 的初始值应设为 0”）。
