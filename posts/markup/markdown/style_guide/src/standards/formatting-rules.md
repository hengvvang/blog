# 第一章：Markdown 基础格式与代码块排版规范

本章详细规范 Markdown 的基础语法与结构定义。我们将从解析引擎（AST，抽象语法树）的视角出发，探讨如何编写兼具源码可读性与渲染一致性的 Markdown 标记，涵盖标题、列表、表格、强调、引用以及无障碍设计。

---

## 1. 标题层级规范 (Heading Structure)

标题是构建文档大纲（TOC）的基础，也是搜索引擎和屏幕阅读器理解页面层级的核心依据。

### 1.1 语法格式

*   **标准 ATX 标题**：必须使用井号（`#`）开头，后接且仅接**一个半角空格**，然后是标题文本。
    ```markdown
    <!-- 正确示例 -->
    ## 编译优化配置

    <!-- 错误示例：缺失半角空格，导致解析引擎将其作为普通文本处理 -->
    ##编译优化配置

    <!-- 错误示例：使用了对称的闭合井号，增加了不必要的源码噪点 -->
    ## 编译优化配置 ##
    ```
*   **严禁使用 Setext 标题**：禁止使用底线形式（下划线 `=` 或 `-`）标记一二级标题。Setext 语法在多人协作中不易维护，且极易与段落底部的分割线、表格分割符产生解析混淆。
    ```markdown
    <!-- 严禁使用以下语法 -->
    编译优化配置
    =============
    ```

### 1.2 层级深度与逻辑约束

*   **单文档单 H1**：每个独立的 Markdown 文件中有且只能有一个一级标题（`#`）。在 mdBook 等文档流中，文件名通常已经映射为侧边栏目录的一级节点，因此正文首行应直接以 `#` 作为文章主标题。
*   **禁止层级跨越**：标题必须按照 `#` $\rightarrow$ `##` $\rightarrow$ `###` $\rightarrow$ `####` 的顺序逐级递增，严禁为了临时调整字号大小而出现 H2 直接跳跃到 H4 的情况。这会导致无障碍读屏器无法建立正确的逻辑导航树。
*   **空行隔离（Blank Line Isolation）**：为了防止部分严格遵循 CommonMark 的解析器将标题与上下游段落误判为同一区块，**标题的前后必须各留有一个空行**。

## 2. 列表嵌套与空格缩进 (List Nesting & Indentation)

列表解析是 Markdown 解析器中最容易产生歧义的部分。CommonMark 规范与 GitHub Flavored Markdown (GFM) 对列表项的缩进有着严苛的定义。

### 2.1 紧凑列表与宽松列表 (Tight vs. Loose Lists)

在 CommonMark 规范中，列表根据其空行分布分为两类：
*   **紧凑列表 (Tight List)**：列表项之间没有任何空行，渲染为不包含 `<p>` 标签的普通 `<li>` 结构。
*   **宽松列表 (Loose List)**：列表项之间存在空行，或者列表项内部包含多段落。此时，渲染出来的 `<li>` 内部会被强制包裹 `<p>` 标签，从而产生较大的段间距。
*   **工程规范**：除非列表项内部需要嵌入代码块或多段文字，否则一律保持紧凑，不加空行。

### 2.2 缩进对齐规则 (4 空格标准)

为了保证在所有渲染引擎（包括 GFM、CommonMark、Pandoc 等）中列表及嵌套块级元素（代码块、引用等）的 AST 能够被正确解析，**嵌套子列表或块级内容必须以父级列表内容字符的起始位置对齐，统一推荐使用 4 个空格作为缩进量**。

#### 2.2.1 无序列表嵌套
推荐使用 `-` 作为无序列表标记（其视觉权重比 `*` 更低，比 `+` 更现代）。
```markdown
- 第一级无序列表项 A
    - 第二级无序列表项 A-1
    - 第二级无序列表项 A-2
- 第一级无序列表项 B
```

#### 2.2.2 列表项中嵌入多段落、块级引用与代码块
当列表项内部含有多个复杂的块级元素时，必须严格使用 **4 空格对齐缩进**。这能确保这些元素在 AST 中作为当前 `list_item` 的子节点，而不是逃逸为独立的全局节点。

```markdown
- 步骤一：配置内核参数
    在系统的 `/etc/sysctl.conf` 文件中添加网络优化参数。如果文件不存在，请手动创建该配置文件。

    > 注意：修改系统级的 sysctl 参数需要具有管理员（root）权限，否则命令将执行失败。

    ```bash
    sudo sysctl -w net.ipv4.ip_forward=1
    ```
- 步骤二：重载配置
    执行以下命令使修改立即生效。
    ```bash
    sudo sysctl -p
    ```
```

#### 2.2.3 有序列表的对齐方式
有序列表的数字序号会随着位数增加而改变宽度（例如从 `9.` 到 `10.`）。在书写时，子级块的对齐仍然建议采用固定的 4 空格缩进，以保持代码的可读性：
```markdown
1.  首先初始化主控制器：
    ```c
    /* 硬件初始化函数 */
    hal_init();
    ```
2.  配置 GPIO 接口。
3.  启动中断服务程序。
```

## 3. 表格排版与语法 (Table Formatting)

表格是呈现多维结构化数据的最佳方式。GFM 扩展表格语法已成为技术文档的事实标准。

### 3.1 基础对齐与分割符

*   **管道符闭合**：表格的每一行（包括表头、分割行和数据行）的左右两侧**必须使用 `|` 进行闭合**。
*   **对齐标记**：
    *   **左对齐**（默认）：`:---`
    *   **右对齐**：`---:`
    *   **居中对齐**：`:---:`
*   **最少破折号限制**：分割行中的破折号数量**不得少于 3 个**（即 `---`），否则部分编译器（如 GFM 规范兼容的编译器）将无法识别为表格结构。

```markdown
<!-- 正确的表格排版示例 -->
| 寄存器名称 | 偏移地址 | 默认值 | 读写权限 | 描述说明 |
| :--- | :---: | :---: | :---: | :--- |
| `USART_SR` | `0x00` | `0x00C0` | rw | 状态寄存器，用于指示发送/接收状态 |
| `USART_DR` | `0x04` | `0x0000` | rw | 数据寄存器，写入即发送，读取即接收 |
```

### 3.2 特殊字符转义与换行处理

*   **管道符转义**：如果表格单元格内部需要包含字符 `|`，必须使用反斜杠进行转义（`\|`），否则会导致表格列解析错乱。
    ```markdown
    | 运算符 | 符号 | 描述 |
    | :---: | :---: | :--- |
    | 或运算符 | `\|` | 按位或操作 |
    | 与运算符 | `&&` | 逻辑与操作 |
    ```
*   **单元格换行**：Markdown 原生表格不支持单元格内段落换行。如需强制换行，可在单元格内插入 HTML 换行标签 `<br />`，并且不要换行书写源码：
    ```markdown
    | 状态码 | 含义说明 |
    | :---: | :--- |
    | `500` | 服务器内部错误。<br />请检查后端服务日志文件 `/var/log/app.log` 以获取堆栈详情。 |
    ```

## 4. 引用与强调规范 (Emphasis & Blockquotes)

强调语法的滥用会严重干扰读者的视觉焦点，破坏段落的连贯感。

### 4.1 粗体与斜体

*   **粗体**：使用双星号 `**强调文本**` 表示，前后与中文混排时需注意空格规范（详见第二章）。
*   **斜体**：使用单星号 `*倾斜文本*` 表示。
*   **规范要求**：在一个文档中，**禁止混用下划线（`_`）和星号（`*`）来表示强调**。应统一使用 `**` 和 `*`，以避免解析引擎在嵌套解析时出错。
*   **禁止过度强调**：严禁整段、整页使用粗体。粗体字数不宜超过当前段落总字数的 15%。

### 4.2 行内代码 (Inline Code)

*   **基础格式**：使用单反引号包裹 `` `code` ``。
*   **反引号转义**：如果行内代码本身包含反引号，必须使用双反引号包裹，且内部左右保留一个空格（此空格在渲染时会被解析器自动过滤）：
    ```markdown
    要在终端输出反引号，可以使用 `` ` `` 符号。
    ```

### 4.3 块级引用 (Blockquotes)

*   **多行引用**：引用的每一行（包括空行）开头都必须包含 `>` 符号，以防文本溢出到引用块之外。
    ```markdown
    <!-- 正确示例 -->
    > 这是一段多行引用的文字。
    >
    > 这是引用的第二段，中间的空行也必须保留 > 标记。

    <!-- 错误示例 -->
    > 这是一段多行引用的文字。

    这是引用的第二段，缺失了 > 标记，渲染时会脱离引用块。
    ```

## 5. 无障碍设计与 SEO (Accessibility & SEO)

高质量的技术文档不仅服务于视觉正常的读者，还应向屏幕阅读器用户以及搜索引擎友好。

### 5.1 图片替代文本 (Image Alt Text)

图片标记格式为 `![Alt text](url)`。
*   **严禁空 alt**：所有插图必须提供有意义的 `alt` 文本。
*   **规范要求**：`alt` 文本应能准确描述图表中的关键信息，避免使用 “image”、“图片”、“untitled” 等无意义词汇。
    ```markdown
    <!-- 推荐写法 -->
    ![STM32 与 ESP32 在 SPI 模式下的主从通信接线图，展示了 MOSI、MISO、SCK 及 CS 的交叉连接方式](images/spi_wiring.png)

    <!-- 不推荐写法 -->
    ![接线图](images/spi_wiring.png)
    ```

### 5.2 链接文本语义化

*   **禁止使用指向性模糊的词汇**：如“点击这里”、“网页”、“参考链接”等。链接文本必须清楚指明跳转的目标内容。
    ```markdown
    <!-- 正确写法 -->
    详细的寄存器配置请参考 [STM32F4xx 中文参考手册](https://example.com/datasheet)。

    <!-- 错误写法 -->
    详细的寄存器配置请点击 [这里](https://example.com/datasheet)。
    ```
*   **新窗口打开外部链接**：mdBook 默认在当前窗口打开所有链接。为了避免用户跳出文档，对于非本站的外部链接，可以使用 HTML 形式的 `<a>` 标签并附带 `target="_blank"` 与 `rel="noopener noreferrer"`：
    ```html
    <!-- 推荐的外链 HTML 书写方式，增强安全性能并保留原窗口 -->
    请查阅 <a href="https://doc.rust-lang.org/std/" target="_blank" rel="noopener noreferrer">Rust 官方标准库文档</a>。
    ```
