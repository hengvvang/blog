# 第一部分：Markdown 排版规则与排版规范

本部分专注于 Markdown 源码本身的排版与语法规范。作为面向多端发布和多人协作的技术文档，其源码的规范性直接决定了编译工具链解析生成的抽象语法树（AST）的健壮性，以及最终读者的阅读体验。

在这一部分中，我们将深入探讨以下两个核心维度的排版准则：

---

## 章节概览

### 1. [第一章：Markdown 基础格式与代码块排版规范](formatting-rules.md)
主要阐述 Markdown 核心标记语言的语法边界与排版约定，包括：
*   **标题层级（Heading Hierarchy）**：建立严谨的 ATX 标题层级，禁止层级跳跃，规范标题前后的空行隔离以满足解析引擎的要求。
*   **列表嵌套与缩进（List Nesting）**：深度剖析紧凑列表（Tight）与宽松列表（Loose）的渲染差异，规范统一采用 4 空格缩进对齐标准，以防列表 AST 树解析崩溃。
*   **表格排版与对齐（Table Alignment）**：采用标准的管道符闭合 GFM 表格语法，规范列对齐标点与特殊字符（如管道符本身）在单元格中的转义方式。
*   **引用与强调（Emphasis & Blockquotes）**：统一强调符号（星号与下划线的界定），以及块级引用的多行嵌套格式。
*   **无障碍设计（Accessibility & SEO）**：落实图片替代文本（Alt Text）的语义化要求，规范外链跳转与屏幕阅读器的兼容性。

### 2. [第二章：表格对齐、特殊字符与文字排版标准](typographic-standards.md)
本章聚焦于“中西文混排”与“中文段落微观排版美学”，旨在解决日常书写中杂乱无章的符号和间距问题：
*   **中西文混排空格（盘古之白）**：汉字与英文字母、阿拉伯数字、行内代码块之间应如何添加半角空格，以及哪些特定场景（如紧邻全角标点、百分号、单位符号）需要禁止空格。
*   **标点符号规范（Punctuation Standards）**：中文语境下全角标点符号（，。、；：？！（）《》）的正确应用，与英文标点的绝对隔离，以及省略号（……）、破折号（——）、连接号（～）的键盘输入与排版准则。
*   **专有名词与技术术语大小写**：建立统一的专有名词库（例如：Git、GitHub、HTML、macOS、mdBook 等），消除拼写和大小写不一致的硬伤。
*   **公式与代码块混排**：规范 Latex 数学公式（行内 $E=mc^2$ 与块级 $$ f(x) $$）以及代码在文本行中的行高配合，避免视觉跳跃感。

## 标准化排版的核心目标

```
+-----------------------------------------------------------+
|                    Markdown 源码排版标准                     |
+-----------------------------------------------------------+
                              │
         ┌────────────────────┴────────────────────┐
         ▼                                         ▼
  【结构语义化 & AST 一致性】                【微观视觉美感 & 可读性】
  - 避免解析引擎（CommonMark）歧义             - 汉字与西文/数字的和谐过渡 (盘古之白)
  - 列表 4 空格对齐, 防止嵌套丢失             - 全半角标点精确区分, 严禁混用
  - 标题不跳级, 生成清晰的目录树               - 代码与公式混排不破坏行高平衡
```

遵循这一套规范，可以让我们的文档不仅在 mdBook 中编译完美，同时在 GitHub, GitLab, VS Code 以及任何标准的 CommonMark 解析器中，都能呈现出一流的纯文本可读性与排版规范。
