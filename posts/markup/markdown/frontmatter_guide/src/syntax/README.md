# 第一部分：Frontmatter 语法与 schema 校验

在前置元数据（Frontmatter）的工程实践中，保障数据的**格式正确性**和**结构合法性**是后续所有模板渲染与自动化集成的基石。

本部分将深入探讨 Frontmatter 的物理语法形态，剖析主流格式的技术细节，并介绍如何建立健壮的校验机制。

---

## 核心内容概述

在开始具体编写和解析元数据之前，我们需要理清两个核心概念：**块语法界定符**与**Schema 校验规则**。

### 1. 语法界定符 (Delimiters)
不同的配置文件格式在 Markdown 文件中拥有专门的物理分界标识，借此告诉编译器如何分割文档：
*   **YAML**：使用前后两组三减号（`---`）包围。由于其最符合直觉的缩进格式，是目前最通用的选择。
*   **TOML**：使用两组三加号（`+++`）包围。在 Go 语言编写的 Hugo 静态生成器中应用最广，具有更好的类型确定性。
*   **JSON**：使用起始 `---json` 与结束 `---` 包围。多用于前后端直连的轻量级工具或不需要额外解析库的原生开发环境。

### 2. 校验规则 (Validation Rules)
由于 Markdown 本身不限制文本输入，编辑者极易写错元数据字段（如多打空格、缺少冒号、拼写错误）。因此，引入模式校验（Schema Validation）是现代内容管线的必经之路。

```
+------------------+         +-----------------+         +------------------+
| Markdown 源文件  | ------> | 正则/词法提取器 | ------> | YAML/TOML 解析器 |
+------------------+         +-----------------+         +------------------+
                                                                  |
                                                                  v (未校验 Object)
+------------------+         +-----------------+         +------------------+
| HTML / 页面输出  | <------ | Zod Schema 校验 | <------ | 静态类型校验引擎 |
+------------------+         +-----------------+         +------------------+
```
