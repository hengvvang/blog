# 第二部分：图表类型与系统文档实践 - 图表与文档

在掌握了 Mermaid 的基础解析原理和渲染架构后，我们需要将精力聚焦于“如何利用 Mermaid 高效、规范地表达具体业务与系统模型”。

本部分将深入讲解主流图表类型的语法规则，并总结在大型分布式系统文档中如何应用防御性排版、版本控制及自动化 CI/CD 编译的最佳工程实践。

---

## 1. 核心图表类型与语法规范概要

不同的系统架构视角需要不同的视图类型来表达。Mermaid 提供了与 UML/工程图相对应的丰富表达手段：

```text
               +--------------------------------------+
               |        Mermaid DSL Source Text        |
               +--------------------------------------+
                                   |
        +------------------+-------+-------+------------------+
        |                  |               |                  |
        v                  v               v                  v
  [Flowchart]          [Sequence]       [State]            [Class]
  有向拓扑流           时序生命周期     状态机转移         静态类/继承
 (Nodes & Edges)      (Actor Timeline)  (FSM States)     (Association/Impl)
```

- **流程图 (`flowchart`)**：表达具有决策、分支、循环特征的系统链路与缓存控制拓扑。
- **时序图 (`sequenceDiagram`)**：刻画高并发、异步微服务之间的调用次序、激活区间及超时退避策略。
- **状态图 (`stateDiagram-v2`)**：模拟复杂实体（如支付网关、订单履约）的有限状态机 (FSM) 变化，是防御非法状态转移漏洞的核心文档。
- **类图 (`classDiagram`)**：描述面向对象系统、设计模式（如策略模式、工厂模式）的静态类继承、实现与关联关系。
- **甘特图 (`gantt`)**：展示项目里程碑、版本发布计划及任务时间跨度的重叠与并行。

## 2. 交互式系统布局最佳实践 (Layout Best Practices)

将文本转换为图表时，布局引擎（如 Dagre）的自由度很大。为了确保图表具备出色的可读性，应遵循以下防御性设计原则：

### 2.1 结构合理分块 (Modular Decomposition)
对于超大型的架构图，**不要试图在一张图表中展示所有细节**。
- **子图隔离 (Subgraph Isolation)**：使用 `subgraph` 强行划定物理边界（如“用户侧”、“网关层”、“数据存储区”），并可以通过给子图设置局部 `direction` 来约束内部节点的排列方式，避免长图拉伸。
- **降低连线交错率**：通过调整节点的声明顺序（Mermaid 按照文本顺序进行初次定位）及使用虚线 (`-.->`) 代替实线 (`-->`) 来弱化异常链路分支，减少布局引擎计算的交叉路径。

### 2.2 防御大图溢出与响应式适配
SVG 图表虽然能无损放大，但在小屏幕或窄版式技术博客中，由于默认的自适应宽度，极易将复杂大图压缩到无法识别的尺寸。
- 在全局配置中开启 `useMaxWidth: true`，使其响应式缩放。
- 通过 CSS 限制外部包装容器的最小宽度，并在超出时提供横向滚动条（即横向溢出滚动防御），保持图中文字字号大小适中。
