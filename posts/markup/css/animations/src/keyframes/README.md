# 第二部分：关键帧动画与渲染性能优化

虽然单次过渡（Transition）能够优雅地解决简单的状态变更，但在面对多阶段循环、多轨道正交运动以及高频微交互时，我们需要引入更强大的**关键帧动画（Animation）**以及浏览器底层的**渲染引擎管线优化**。

本部分将深度剖析 `@keyframes` 动画的时间轴控制，深入渲染管线内部以洞察重排（Reflow）、重绘（Repaint）与合成（Composite）的开销，并解析如何通过 GPU 硬件加速和图层提升打造极致流畅的微交互动效。

---

## 1. 关键帧时间轴（Keyframe Timeline）机制

`@keyframes` 定义了一个参数化的时间轴，浏览器在其内部划分出多个时域区间，并按百分比指定的状态进行局部插值：

```text
    时域区间 1                    时域区间 2                    时域区间 3
 0% ────────────( ease-in )────────────> 50% ────────────( linear )───────────> 80% ────────( ease-out )────────> 100%
[P0: 初始状态]                        [P1: 中间状态 A]                       [P2: 中间状态 B]                      [P3: 最终状态]
```

每一个百分比节点代表一个局部航标状态，两个相邻百分比节点之间的插值计算会独占一个时域插值函数（Timing Function）。

---

## 2. 核心控制属性

CSS 动画的运行由一系列强大的控制属性联合约束：
*   **`animation-fill-mode`**：定义动画在未启动（如延迟阶段）和结束后的行为，包括样式是复位（`none`）、前向保留（`forwards`）、后向应用（`backwards`）还是双向应用（`both`）。
*   **`animation-play-state`**：通过设置 `paused` 与 `running`，可以原位冻结或恢复动画的执行，避免重置渲染状态。
*   **`animation-direction` & `iteration-count`**：控制动画的往复行为（如 `alternate`）和循环计数。

## 3. GPU 硬件加速与复合图层提升

为了实现 60 FPS / 120 FPS 的丝滑流畅度，我们必须将动画元素从浏览器的主线程绘制（CPU）卸载至 GPU 进行硬件加速。

### 浏览器图层合并树（Compositing Tree）架构

```text
     [ DOM 树 ]
         │
         ▼
  [ 布局树 Layout Tree ] ──> 计算元素几何排版 (重排 Reflow)
         │
         ▼
  [ 绘制层 Paint Layers ] ──> 栅格化生成位图 (重绘 Repaint)
         │
         ▼
[ 复合图层 Composited Layers ] ──> GPU 显存纹理缓存与变换 (仅合成 Composite)
  ├── 复合图层 1 (基底层 - CPU 渲染)
  └── 复合图层 2 (显式提升层 - GPU 硬件加速: will-change: transform)
```

当我们使用 `will-change: transform, opacity` 显式提升元素为复合图层时，浏览器会直接跳过 Layout 和 Paint 阶段，将纹理保存在 GPU 中，通过合成线程直接控制图层的缩放、倾斜、平移和透明度变换。这消除了昂贵的主线程重绘开销。

## 4. 微交互（Microinteractions）设计理念

微交互是指 UI 界面中对特定用户行为的细微、快速响应（通常小于 200ms）。高质量的微交互要求：
1.  **极速响应**：输入与动效启动延迟在 1 帧（16ms）之内，避免操作粘滞感。
2.  **物理真实**：使用具有弹性和质量感（阻尼系数）的过渡，拒绝线性生硬。
3.  **零性能损耗**：严格在 GPU 复合图层内进行三维仿射变换，为用户提供纯粹的丝滑触觉反馈。
