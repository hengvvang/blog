# GNU 内联汇编

当高级编程语言（如 C/C++）无法直接操纵底层硬件，或者当我们需要榨干处理器的每一滴性能时，**内联汇编（Inline Assembly）** 便是连接高级语言与底层机器的终极桥梁。在操作系统内核、裸机硬件驱动、高频事务处理以及嵌入式开发等领域中，内联汇编是不可或缺的底层编程利器。

本部分将系统介绍 GNU 扩展内联汇编的语法架构和使用规范，重点包含以下内容：
1. **四段式语法规则**：剖析 `__asm__ __volatile__ ( 模板 : 输出 : 输入 : 破坏 )` 各部分的作用。
2. **约束限制（Constraints）**：理解通用寄存器约束（`r`）、内存约束（`m`）、立即数约束（`i`）等，以及如何正确绑定 C 语言变量与硬件寄存器。
3. **修饰符（Constraint Modifiers）**：掌握只写（`=`）、可读可写（`+`）以及防止寄存器共享冲突的早期擦除修饰符（`&`, Earlyclobber）。
4. **Volatile 操作与内存屏障**：深入理解 `__volatile__` 关键字和 `"memory"` 破坏符如何阻止编译器的过度优化与指令重排。

## 编译器与内联汇编的关系

在传统的无约束内联汇编中，编译器将汇编视为一个“黑盒”。但在 GNU 扩展内联汇编中，编译器通过“输入/输出约束列表”与汇编代码协同工作。

```
                    C 语言变量 (例如: int val)
                               │
                 ┌─────────────┴─────────────┐
                 ▼ (编译期寄存器分配器)       ▼
         寄存器分配 (例如: r0)       物理内存地址 (例如: [sp, #4])
                 │                           │
                 └─────────────┬─────────────┘
                               ▼ (按约束替换占位符 %0, %1...)
                    生成最终的物理汇编指令
```

* **安全绑定的必要性**：编译器不知道汇编代码的实际语义，它只通过你声明的约束来做寄存器分配。如果约束声明错误，GCC 可能会在优化阶段把尚未使用的输入变量所占用的寄存器提前覆盖，或者重排掉与外部内存相关的汇编指令，从而导致系统崩溃。
* **Volatile 的作用**：防止汇编块被优化掉或被移出循环。在包含硬件外设操作、中断开关或缓存屏障的场景中，必须要用 `volatile` 声明，明确告知编译器该段代码具有隐藏的副作用。
