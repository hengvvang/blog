在嵌入式裸机开发中，程序的构建过程并非一蹴而就。本部分将深入探讨可执行文件（ELF）的生命周期，从源文件编译、汇编到链接器的地址重定位，揭示这一系列底层演变过程。

## 本部分核心主题

## 物理存储与程序段映射概览

在微控制器上电时，Flash 中存放着完整的程序镜像。上电后，C 运行时环境（Startup Code）将特定的段搬移或初始化到 SRAM 中，以便 CPU 能够进行高效读写。

下面是一个标准的 ARM Cortex-M 物理/虚拟存储映射示意图：

```text
+----------------------- 0x08080000 (Flash 结束 - 512KB)
|                       |
|   未使用的 Flash 空间  |
|                       |
+-----------------------
|   .data 初始化数据源值|  <--- 存储在 Flash (LMA)
+-----------------------
|   .rodata 只读数据段  |
+-----------------------
|   .text 代码段        |
+-----------------------
|   .isr_vector 向量表  |  <--- 必须存放在 0x08000000
+----------------------- 0x08000000 (Flash 起始)

=========================

+----------------------- 0x20020000 (SRAM 结束 - 128KB)  <--- 栈顶指针 (MSP) 指向此处
|      向下生长的栈     |  |
|         (Stack)       |  v
+ - - - - - - - - - - - +
|                       |
|    未使用的 SRAM 空间 |
|                       |
+ - - - - - - - - - - - +
|         (Heap)        |  ^
|      向上生长的堆     |  |
+-----------------------
|   .bss 未初始化数据段 |  <--- 上电清零 (SRAM VMA)
+-----------------------
|   .data 运行副本段    |  <--- 从 Flash 拷贝至此运行 (SRAM VMA)
+----------------------- 0x20000000 (SRAM 起始)
```

在接下来的章节中，我们将对上述内存排布背后的链接语法、重定位原理以及加载/运行地址（LMA/VMA）的区别进行最为严谨的剖析。
