# 引言

在现代软件工程实践中，版本控制系统（VCS）不仅仅是一个“代码备份”工具，更是团队协作、代码评审（Code Review）、持续集成（CI/CD）以及历史回溯的重要基础设施。Git 作为事实上的行业标准，提供了极其丰富的分支管理与历史操作工具。

然而，在日常的高频迭代开发中，由于本地开发的快速尝试和频繁调试，开发者往往会产生大量琐碎、无序且缺乏逻辑关联的本地提交。例如频繁出现的 `WIP`（Work In Progress）、`fix typo`、`debug test` 以及各种为了测试 CI 流程而产生的临时 Commit。如果直接将这些未经整理的“脏历史”合并并推送到公共主干分支，会导致项目历史树变得盘根错节、难以卒读，不仅增加了代码评审人员的心理负担，也为后续的代码追溯（如 `git bisect`）与线上故障回滚带来了巨大的隐患。

**交互式变基（Interactive Rebase，即 `git rebase -i`）** 正是为了解决这一痛点而生的“手术刀”级工具。它允许开发者在将代码推送到远端之前，在本地以精细、受控的方式重构和修剪提交历史。无论是合并微小的拼写修复、修改错误的提交信息、拆分庞大的单次提交，还是彻底删除误引入的文件，交互式变基都能提供极其强大的技术支撑。

## 本书概览

本手册旨在为中高级系统工程师与开发人员提供一份**生产级、全景式的 Git 交互式变基实战指南**。全书结构重组为两大核心部分：

### 第一部分：分支合并与变基原理对比

本部分致力于从底层原理与图论模型出发，深入剖析 Git 分支演进的核心机制。

- **[合并与变基](concepts/README.md)**：作为第一部分的导读，介绍合并与变基的根本哲学差异，讨论分支集成的几种主要形态（Fast-forward 与 3-Way Merge）。
- **[第一章：Git Merge 与 Rebase 底层原理及历史线对比](concepts/rebase-vs-merge.md)**：深入剖析 `git merge`（三方合并）与 `git rebase`（差异重放）的底层数据结构。探讨三方合并产生的 Merge Commit 对历史线索的影响，以及 Rebase 带来的单线型历史（Linear History）的优劣势。最后明确划定变基的“黄金法则”（The Golden Rule of Rebase）与团队协作边界。

### 第二部分：交互式变基与工程提交整理

本部分聚焦于实战操作，详尽剖析如何利用交互式变基对历史进行修剪、重构，以及解决随之而来的冲突。

- **[交互式变基](rebase/README.md)**：作为第二部分的导读，快速梳理交互式变基的 Todo 文件概念，简述 `edit`、`squash`、`fixup`、`drop` 等动作对分支的重塑，以及如何利用自动合并提升效率。
- **[第二章：交互式变基 Todo 文件操作规范](rebase/interactive-rebase-todo.md)**：详解运行 `git rebase -i` 后弹出的调度清单文件（Todo List）的内部机制。逐一剖析现代 Git 版本中支持的各项核心变基指令：`pick`、`reword`、`edit`、`squash`、`fixup`、`exec`、`drop`、`break` 以及针对复杂历史的标签与重置操作（`label`、`reset`、`merge`）。
- **[第三章：分支线性整理与冲突解决实战](rebase/advanced-rebase-tricks.md)**：直击实际开发中的高频痛点与高级应用场景，包括**拆分提交（Splitting Commits）**、**冲突解决流程（Conflict Resolution）**、**跨越基底的变基（Rebase with `--onto`）**、**自动变基流（Auto-squashing）**、**灾难恢复（Safety Recovery via Reflog）** 以及**处理合并提交（Handling Merge Commits）**。

## 学习目标

完成本书的学习与实战演练后，你将能够：

1. **深刻理解 Git 历史树的拓扑演变**：在 Rebase 与 Merge 之间做出最符合项目现状的决策，并能够在复杂的项目依赖中清晰理清主线和分支关系。
2. **熟练驾驭交互式变基 Todo 清单**：能够根据团队代码评审（Code Review）的要求快速修剪本地提交，输出“如艺术品般干净”的线性提交历史。
3. **沉着应对变基过程中的各种合并冲突**：掌握系统化的冲突排查与中止机制，厘清变基冲突与普通合并冲突在 HEAD 指向上的根本反差。
4. **具备极端情况下的容灾能力**：不再害怕因为 Rebase 导致“代码丢失”，能够运用 `reflog` 找回任何曾被 Git 追踪过的代码快照，具备毫秒级无损挽救现场的能力。
5. **在团队中建立规范的 Git 提交文化**：利用自动化工具（如 Git hooks、autosquash 机制）提高团队整体的交付质量与协作效率。

> [!IMPORTANT]
> 交互式变基是一种具有“破坏性”的历史重写工具。在熟练掌握其核心机理前，建议在本地建立临时的测试分支进行演练。请时刻铭记：**不要对任何已经推送到共享远端分支的提交进行变基**。
