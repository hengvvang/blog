# 第一部分：交叉编译概念与寻址

在嵌入式开发领域，**交叉编译（Cross Compilation）**是连接桌面开发机与物理微控制器（MCU/MPU）的核心桥梁。要构建稳定、高效的嵌入式构建流水线，我们必须首先掌握这一领域的基础概念。

本部分将带你深入理解以下三个核心议题：

## 1. 主机与目标机架构 (Host vs Target Architectures)

*   **主机 (Host)**：指运行 CMake 和编译器、链接器等开发工具的平台（例如你的 x86_64 Windows/Linux PC，或者 Apple Silicon ARM64 Mac）。
*   **目标机 (Target)**：指最终运行所编译程序的目标微控制器或微处理器平台（例如 Cortex-M4 架构的 STM32、RISC-V 架构的 GD32 或 ESP32）。
*   **物理鸿沟**：两者的 CPU 指令集（CISV vs RISC，Thumb-2 编解码）、寄存器结构、内存管理机制（虚拟内存 vs 扁平物理寻址）存在物理上的根本不同。因此，主机上运行的编译器必须能够“理解”并生成完全属于目标机指令集的高效二进制机器码。

```text
+------------------------------+                       +------------------------------+
|       主机平台 (Host)         |                       |     目标机平台 (Target)       |
|  - 架构: x86_64 / AArch64    |   编译输出 Target     |  - 架构: ARM Cortex-M/RISC-V |
|  - 内存: 虚拟内存 (GB 级)     |======================>|  - 内存: 物理扁平 SRAM (KB 级)
|  - 系统: Win/Linux/macOS     |     (烧录固件)        |  - 系统: 裸机 (Bare-Metal)   |
+------------------------------+                       +------------------------------+
```

## 2. 系统根目录 (Sysroot / System Root)

在交叉编译中，编译器必须定位到目标平台专属的**系统根目录（Sysroot）**，该目录中包含了：
*   **目标架构专属的 C/C++ 标准库头文件**（如 `<stdio.h>`、`<stdint.h>` 等）。
*   **编译好的目标架构静态库文件**（如 `libc.a`、`libm.a`、`libnosys.a` 等）。

**绝对隔离原则**：在交叉编译过程中，必须严格禁止编译器包含主机系统的头文件目录（如 Linux 的 `/usr/include` 或 `/usr/lib`），否则会导致严重的平台架构冲突（如将 x86 汇编符号引入 ARM 构建，导致符号大小不匹配或未定义指令）。

## 3. 编译环境与工具链定位

我们将探讨目标三元组（Target Triplet）的命名范式，理清汇编器、链接器以及各种二进制处理工具（如 `objcopy`、`size`、`objdump`）如何与编译器前端有机整合，形成一个能够输出裸机二进制镜像的闭环环境。
