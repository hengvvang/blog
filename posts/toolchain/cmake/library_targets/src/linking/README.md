# 库类型与链接

在现代 C/C++ 工程中，构建系统的核心职责之一是定义、编译并将各种形式的源代码组织为可复用的库，以及管理这些库与下游可执行程序之间的链接关系。理解不同库类型的物理本质及其在编译、链接阶段的底层运作机机制，是编写健壮、高效构建配置的基础。

---

## 1. 静态库、动态库与接口库的物理本质

在底层操作系统与工具链的视角下，各种库类型具有完全不同的物理形态与生命周期：

1.  **静态库 (Static Library, `*.a` / `*.lib`)**：
    *   **物理本质**：实质上是**对象文件 (Object Files, `*.o` / `*.obj`) 的无损归档包**（类似于 tar/zip 压缩包，但未压缩）。
    *   **编译期行为**：构建静态库时，编译器仅执行汇编阶段生成 `.o`/`.obj` 文件，随后由归档器 (Archiver，如 `ar` 或 `lib.exe`) 将其打包。在此阶段不发生任何符号决议或重定位。
    *   **链接期行为**：下游目标链接静态库时，链接器会解析静态库中的符号表，提取出包含被引用符号的对象文件，并将这些对象文件的代码段、数据段直接“复制合并”到最终的二进制目标中。
2.  **动态库 (Shared/Dynamic Library, `*.so` / `*.dylib` / `*.dll`)**：
    *   **物理本质**：是一个**已链接完成的、具备完整段结构和符号表的共享二进制文件**。
    *   **编译期与链接期行为**：在编译动态库时，编译器通常必须生成位置无关代码 (Position Independent Code, PIC)，并由链接器执行完整的符号定位和链接。当可执行程序链接动态库时，链接器并不复制代码，而是在可执行文件中记录下对该动态库的依赖关系及导入符号表（在 Windows 下需链接特殊的导入静态库 `*.lib`）。
    *   **运行时行为**：在程序启动或运行期间，由操作系统的动态链接器 (如 `ld.so`、`dyld` 或 Windows 内核的加载器) 将动态库加载到物理内存中，并在进程的虚拟地址空间中完成符号的重定位与绑定。
3.  **接口库 (Interface/Header-only Library)**：
    *   **物理本质**：在物理磁盘上**不生成任何二进制产物**。它纯粹是 CMake 逻辑层面的“元数据容器”。
    *   **作用**：主要用于封装 Header-only 库（如高度模板化的现代 C++ 库），或者封装纯粹的编译属性组合（如全局警告选项、特定编译器宏定义等），并依赖 CMake 的属性传播链自动向下游消费者注入编译和链接参数。

---

## 2. 编译与链接的底层流转机理

当我们在 CMake 中配置链接关系时，构建系统会协调编译器与链接器完成以下两阶段任务：

### 2.1 编译阶段 (Compilation Stage)
每一份独立的源文件 (`*.cpp`) 被单独编译为包含机器码但未确定虚拟地址的对象文件 (`*.o`/`*.obj`)。在此阶段，如果代码中调用了外部符号，编译器仅通过头文件 (`*.h`/`*.hpp`) 的声明来确认符号签名，并在对象文件的未决符号表 (Undefined Symbol Table) 中留空。

### 2.2 链接阶段 (Linking Stage)
链接器将所有输入的对象文件和库进行符号决议 (Symbol Resolution) 和地址重定位 (Address Relocation)。

*   **静态链接**：链接器从归档包中搜寻未决符号的定义，一旦找到，便将整个对象文件拷贝至最终的输出文件中，重新计算所有内部跳转的相对/绝对地址。
*   **动态链接**：链接器不拷贝代码，而是验证符号的存在性，并在最终二进制文件的 `.dynamic` 段中写入所需的动态链接库名称，以及在 `.dynsym` 段中写入导入/导出符号描述符。

### 编译链接数据流向与控制模型：

```
[ 源文件 .cpp ] --(编译器 gcc -c)--> [ 对象文件 .o / .obj ]
                                           |
                  +------------------------+------------------------+
                  | (归档打包)                                       | (动态链接)
                  v                                                 v
         [ 静态库 .a / .lib ]                              [ 动态库 .so / .dll ]
                  |                                                 |
                  | 链接期完整复制段                                | 链接期仅记录符号依赖
                  +------------------------>+<----------------------+
                                            |
                                            v
                                   [ 最终可执行文件 ]
                                            |
                                            v 运行时加载
                                  [ 动态链接器 (ld.so) ] <---> 载入内存中的 .so/.dll
```

本部分第一章将带您深入探讨这四种库类型在现代 CMake 中的具体定义规范、符号可见性控制、对象库与接口库的演进，以及如何利用现代 CMake 避免传统构建的全局污染。
