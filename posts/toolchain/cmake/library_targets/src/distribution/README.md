# 现代属性与分发

在大型软件系统的演进过程中，如何将复杂的模块依赖网络理清、避免编译选项污染，以及如何以标准、规范的工业级格式分发构建产物，是决定软件架构质量的重要考量。现代 CMake（3.0+）通过“目标属性的继承传播”以及“一等公民级别的安装导出机制”交出了完美的答卷。

---

## 1. 基于 Target 的属性传播与可见性控制

现代 CMake 的核心思想是**以目标（Target）为建模实体，通过属性（Property）表达特征，通过可见性控制流转**。

*   **属性模型**：每个 Target 都持有多组以 `INTERFACE_` 为前缀或无前缀的属性。非前缀属性（如 `INCLUDE_DIRECTORIES`）决定目标“自身如何编译”；而带 `INTERFACE_` 前缀的属性（如 `INTERFACE_INCLUDE_DIRECTORIES`）决定目标“如何被下游消费者编译”。
*   **可见性修饰符**：
    *   `PRIVATE`：只影响自身构建，不向下游传播。
    *   `INTERFACE`：自身构建不感知，仅作为接口标准向下游传播。
    *   `PUBLIC`：既影响自身，也向下游强力传播。

通过这套机制，复杂的头文件包含路径、宏定义、编译选项等均可在依赖网络中自动传递，消除了传统的全局变量污染，构建出了健壮的“图状”依赖树。

---

## 2. 导出、版本与打包发布规范

一个符合现代软件工程标准的库，不应当只是简单地把编译出来的二进制文件和头文件丢给用户，而是应当随同分发一份“自描述”的 CMake 描述文件，支持标准的 `find_package` 调用。

完整的发布规范通常包含：
1.  **导出目标文件 (Target Export, `*Targets.cmake`)**：记录了被导出 Target 的所有 `INTERFACE_*` 属性，下游项目链接该导入目标时，就能够自动获取库的路径、必须链接的次级依赖以及必须包含的头文件目录。
2.  **包配置文件 (Package Config, `*Config.cmake`)**：作为下游 `find_package` 的入口点，它负责安全地引入外部依赖（如 `find_dependency`），并导入目标文件。
3.  **版本匹配文件 (Config Version, `*ConfigVersion.cmake`)**：定义了版本兼容策略（如 `SameMajorVersion`），确保下游在请求特定版本的库时，能进行精确的版本匹配和安全报错。

### 属性传播与打包发布生命周期：

```
[ 源码级定义 ] ──(PUBLIC/PRIVATE)──> [ 属性图构建 (Build Tree) ]
                                              │
                                              │ CMake 生成器表达式解耦
                                              ▼
[ 导出目标定义 ] ──(*Targets.cmake)──> [ 安装发布包 (Install Tree) ]
                                              │
                                              │ 配合 *Config.cmake 注册
                                              ▼
[ 外部下游项目 ] ──(find_package)───> [ 自动解析并链接依赖 (一键集成) ]
```
