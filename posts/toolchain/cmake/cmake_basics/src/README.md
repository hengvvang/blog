# CMake 构建宏编写与自动化 CI/CD 环境结合运用

在现代 C/C++ 软件工程与嵌入式开发中，构建系统（Build System）的质量直接决定了项目的开发效率、可维护性与跨平台协作的稳定性。传统的 Makefile 虽在小型单体项目中表现灵活，但在面对复杂的跨平台移植、多目录依赖解析、第三方库整合以及自动化持续集成（CI/CD）时，其手写维护成本往往呈指数级增长。

**CMake** 作为现代 C/C++ 构建生成器（Build Generator）的行业事实标准，通过引入**声明式目标驱动（Target-based CMake）**的构建理念，极大地规范了构建逻辑的组织方式。它不直接负责代码的编译和链接，而是读取顶层的描述文件 `CMakeLists.txt`，进而为底层的构建工具（如 Make、Ninja、MSBuild 等）生成对应的平台专属构建配置文件。

```text
                                  +-----------------------+
                                  |   CMakeLists.txt      |
                                  |  (声明式构建描述文件) |
                                  +-----------------------+
                                              |
                                      [ 配置与生成阶段 ]
                                              v
                      +-----------------------+-----------------------+
                      |                       |                       |
                      v                       v                       v
            +-------------------+   +-------------------+   +-------------------+
            |  Unix Makefiles   |   |   Ninja Build     |   |   MSBuild (VS)    |
            |   (Makefile)      |   |  (build.ninja)    |   |    (.sln/.vcxproj)|
            +-------------------+   +-------------------+   +-------------------+
                      |                       |                       |
                  [ make ]                 [ ninja ]              [ msbuild ]
                      +-----------------------+-----------------------+
                                              | [ 编译与链接 ]
                                              v
                                  +-----------------------+
                                  |   二进制程序 / 库文件 |
                                  |    (ELF/EXE/SO/DLL)   |
                                  +-----------------------+
```

本教程旨在为中高级系统工程师、嵌入式开发者提供一份**生产级**的 CMake 工程构建指南。本书不仅涵盖 CMake 的基础语法、变量作用域与高级控制结构，还将深入探讨多层目录的项目布局、库的可见性管理、链接器脚本（Linker Script）的精确集成，并最终将其延伸至现代 CI/CD 自动化流水线（如 GitHub Actions 与 GitLab CI）的整合。

## 章节大纲与核心内容

本书结构环环相扣，从单文件与基础语法起步，逐步演进至复杂的工业级多目录项目，最后在云端 CI/CD 环境中落地。整体架构如下：

### 第一部分：CMake 语法与变量基础

1. **[引言](README.md)**
   - 介绍本书的主题、现代构建系统的痛点以及 CMake 的重要作用。
2. **[第一章：CMake 基础语法与核心概念](syntax/cmake-intro-syntax.md)**
   - **运行机理**：探究 CMake 的生命周期（配置、生成与构建三阶段）与内部机制。
   - **变量系统**：深度解析局部变量、缓存变量与环境变量的作用域与生存周期。
   - **流程控制**：详细阐述条件分支、循环结构，以及宏（Macro）与函数（Function）的底层差异。
   - **参数解析**：使用 `cmake_parse_arguments` 模块编写健壮的、参数可配置的库声明宏。

### 第二部分：项目结构化与分发

3. **[第二章：多目录项目构建与结构化布局](structure/multidir-project.md)**
   - **目录结构**：搭建规范的生产级 C/C++ 多目录工程结构（`src/`、`include/`、`lib/`、`tests/`）。
   - **面向目标构建**：深入对比 `target_link_libraries`、`target_include_directories`、`target_compile_options` 的使用，剖析 `PUBLIC`、`PRIVATE` 与 `INTERFACE` 的属性传递效应。
   - **底层构建操作**：编写自定义构建命令（`add_custom_command`）与自定义目标（`add_custom_target`）。
   - **嵌入式定制**：集成 GCC 链接器脚本（`.ld`）与 Map 文件生成，并自动导出 Binary/Hex 固件。
4. **[第三章：自动化构建与 CI/CD 环境整合](structure/ci-cd-integration.md)**
   - **交叉编译**：编写并传递工具链文件（`toolchain-arm.cmake`）来适配 ARM Cortex-M 等嵌入式硬件。
   - **构建类型管理**：精细解析 Debug、Release、MinSizeRel、RelWithDebInfo 等构建类型的底层行为差异。
   - **单元测试**：使用 CTest 模块整合测试案例。
   - **质量守门员**：集成 `clang-tidy` 静态检查与 `clang-format` 代码格式化。
   - **CI 流水线实战**：编写高效的 GitHub Actions 和 GitLab CI 配置文件，引入 CCache 编译缓存，优化编译速度。

## 读者预期收获

通过对本书的系统性阅读与实装演练，您将能够：
- **解构复杂 C/C++ 项目**：快速理清其构建拓扑与依赖链条，具备重构巨型项目构建系统的能力。
- **掌握现代 Target-based 设计**：淘汰过时的全局变量注入式配置，使用干净的目标属性隔离，实现高度模块化与解耦。
- **设计并维护工业级交叉编译项目**：能够精细配置裸机嵌入式芯片的内存空间、中断向量以及编译优化选项。
- **落地云端持续集成流水线**：让编译、代码规范检查、单元测试、测试覆盖率收集、固件生成与发布全部在云端自动完成，构建高内聚的 DevOps 工作流。
