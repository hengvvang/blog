# 内存布局与物理划分

对于运行在通用操作系统（如 Linux）之上的高级语言程序而言，程序员通常只需关注程序逻辑本身，而无需考虑变量究竟被存放在哪一块物理芯片上。但在嵌入式 MCU 开发中，物理内存是有限的且极具差异化的。

要想编写出高效、稳定的嵌入式代码，首要任务就是彻底搞清楚微控制器内部的物理存储介质（主要是 Flash 和 SRAM）是如何组织起来的，以及我们的 C 代码经过编译、链接后，所生成的各个内存段（Segments/Sections）是如何被分派到这些物理介质之上的。

---

## 物理存储介质：Flash 与 SRAM

在嵌入式 MCU 中，程序的执行和数据的保存依赖于两种截然不同的半导体存储技术：

```
                             +-------------------+
                             |  MCU Address Map  |
                             +---------+---------+
                                       |
                  +--------------------+--------------------+
                  |                                         |
        +---------v---------+                     +---------v---------+
        |   Flash Memory    |                     |    SRAM Memory    |
        +-------------------+                     +-------------------+
        | - 非易失性 (只读) |                     | - 易失性 (可读写) |
        | - 存放指令与常量  |                     | - 存放运行期数据  |
        | - 读取稍慢/需Wait |                     | - 零等待周期读取  |
        +-------------------+                     +-------------------+
```

1. **Flash Memory（闪存）：**
   * **角色：** 程序代码和静态常量数据的“永久居所”。
   * **特点：** 掉电后数据不丢失，读取速度虽快但相较于 CPU 核心可能存在延迟（需配置 Wait State），写入和擦除需要特定的控制器算法支持。
   * **存储段：** 主要是只读的代码段（`.text`）和只读数据段（`.rodata`），此外还包含可读写全局变量（`.data`）的初始值镜像。

2. **SRAM（静态随机存储器）：**
   * **角色：** 程序运行时的“临时工作区”。
   * **特点：** 掉电后数据丢失，但读写速度极快（通常为单周期访问），可随意读写。
   * **存储段：** 可读写全局变量段（`.data`、`.bss`）、程序动态堆栈空间（Stack）以及堆（Heap）空间。

---

## 程序核心段（Sections）及其生存期

编译链接生成的 ELF 可执行文件包含许多段，它们在 MCU 运行时的职责与属性如下：

* **`.text`（代码段）：** 
  存放微控制器执行的机器指令（如 ARM 汇编指令）。由于它是只读的，在运行期间直接保留在 Flash 中，CPU 通过 I-Code 总线对其进行取指。
* **`.rodata`（只读数据段）：** 
  存放程序中定义的常量数据，如 `const char table[]` 或字符串常量。这部分数据同样是只读的，通常直接驻留在 Flash 中，CPU 通过 D-Code 总线读取。
* **`.data`（已初始化全局数据段）：** 
  存放**已显式初始化且初始值不为 0** 的全局变量和静态变量（如 `int g_val = 100;`）。它们在运行期必须驻留在 SRAM 中以便修改，但由于它们具有确定的初值，在固件烧录时，其初值镜像被保存在 Flash 中，上电后由启动代码拷贝至 SRAM。
* **`.bss`（未初始化全局数据段）：** 
  存放**未初始化或显式初始化为 0** 的全局变量和静态变量（如 `int g_zero = 0;` 或 `int g_buf[100];`）。这部分变量上电时的初始值规定为 0。因为不需要初值镜像，所以在 Flash 中不占空间。上电后由启动代码在 SRAM 中将其清零。
* **Stack（栈区）：** 
  用于存放函数的局部变量、函数调用参数、函数返回地址，以及中断发生时硬件自动保存的现场寄存器。栈由编译器和 CPU 硬件指针（SP）自动管理，随函数调用动态生长与消亡。
* **Heap（堆区）：** 
  由程序员通过 `malloc()`、`free()` 等标准 API 手动进行管理的动态内存分配区域。在资源紧张的嵌入式 MCU 中，为了防止内存碎片和内存泄漏，通常对堆的使用非常谨慎。

## 编译、加载与运行的全局视图

从 C 源码到最终物理内存的映射，可以通过下述关系视图来理解：

```
  C 源码阶段                编译链接阶段                上电加载/运行阶段
+------------+             +-------------+            +---------------------+
|  C 源代码  | --编译-->   |  ELF文件段  | --烧录-->  | Flash (物理介质)    |
|  (变量定义  |             |  .text      |            |  - 中断向量表       |
|   与指令)  |             |  .rodata    |            |  - .text            |
+------------+             |  .data      |            |  - .rodata          |
                           |  .bss       |            |  - .data (初始镜像) |
                           +-------------+            +---------+-----------+
                                                                | (上电拷贝)
                                                                v
                                                      +---------------------+
                                                      | SRAM (物理介质)     |
                                                      |  - .data (运行态)   |
                                                      |  - .bss (清零)      |
                                                      |  - Heap (动态分配)  |
                                                      |  - Stack (局部堆栈) |
                                                      +---------------------+
```
