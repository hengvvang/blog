# 字节对齐与总线访问约束

在理想的软件世界中，我们可以认为内存是一个连续的字节数组，CPU 可以自由地在任意字节地址读取或写入任意长度的数据。然而，在真实的硬件世界中，微控制器的总线架构和存储器颗粒对数据的读取和写入有着严格的物理限制。

如果忽略了底层的内存对齐规则，不仅会导致 CPU 访问数据的性能大幅下降，甚至可能在一些硬件平台上直接导致系统抛出硬件异常（Fault）而死机崩溃。

本部分将深入研究内存对齐的物理原因、C 语言结构体的对齐与填充规则，以及在 ARM Cortex-M 处理器上由非对齐内存访问引发的总线异常（Bus Fault）的底层机制与调试诊断方法。

---

## 核心概念概览

本部分主要涵盖以下三个核心概念：

### 1. 内存对齐的本质原因
微控制器的数据总线宽度通常是 32 位（4 字节）或 64 位（8 字节）。为了实现最高效的数据传输，CPU 每次发起总线周期都是成块地读取对齐地址上的数据。非对齐访问会强迫总线控制器发起多次读取周期，并在处理器内部进行数据拼接，严重降低了执行效率。

```
对齐的 32 位数据读取 (只需一次总线访问)：
[ 0x20000000 - 0x20000003 ]  ===>  CPU 一次读入

非对齐的 32 位数据读取 (需要两次总线访问 + 内部拼接)：
[ 0x20000000 - 0x20000003 ]  ===>  读取前半部分数据
[ 0x20000004 - 0x20000007 ]  ===>  读取后半部分数据
                                     CPU 拼接并输出
```

### 2. 结构体对齐与填充（Padding）
为了确保每个结构体成员都能位于其“自然对齐”的物理地址上，编译器会在结构体成员之间以及结构体尾部自动插入一些无用的空闲字节，这就是**填充字节（Padding）**。
理解结构体的填充规则（成员首地址对齐、结构体总体长度对齐），有助于我们在编写代码时合理优化结构体成员的排列顺序，节省宝贵的 SRAM 空间。

### 3. 非对齐内存访问约束
并非所有的嵌入式处理器都能够容忍非对齐访问。
* 像 **ARM Cortex-M0/M0+/M1** 这样的内核，在硬件上完全不支持非对齐地址的数据读写，一旦遇到，会立刻抛出 `HardFault`。
* 像 **Cortex-M3/M4/M7** 这样的内核，虽然硬件支持大多数非对齐访问，但部分指令（如多数据加载 `LDM`、双字加载 `LDRD` 等）依然有着硬性对齐要求。此外，我们也可以通过配置系统寄存器主动捕获非对齐行为，以协助排查潜在的代码漏洞。
