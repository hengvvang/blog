# 概述：嵌入式 MCU 内存布局与对齐限制

在现代通用操作系统（如 Linux、macOS 或 Windows）中，应用程序运行在高度抽象的虚拟内存空间（Virtual Memory Space）之上。由操作系统的内存管理单元（MMU）负责将虚拟地址映射到物理内存。这种设计提供了强大的进程隔离性、按需分页、写时复制等高级特性，使得应用程序无需关注底层的物理存储介质分布。

然而，在嵌入式微控制器（MCU，如 ARM Cortex-M 系列、ESP32、RISC-V 等）的裸机（Bare-metal）或实时操作系统（RTOS）环境下，**物理地址就是逻辑地址**。程序直接在物理内存上运行，没有虚拟内存的隔离保护，也没有页表和地址映射的开销。这意味着，开发人员不仅需要清晰地理解物理存储介质（如 Flash、SRAM、TCM、CCM）的硬件特性，还要深刻掌握编译器与链接器如何将 C 语言代码编译并映射到具体的段（Section）中。

此外，由于嵌入式处理器总线架构（如 AHB、APB、AXI）对数据传输边界的硬性限制，内存对齐（Memory Alignment）与非对齐访问规则（Unaligned Access Rules）成为了直接关系到系统稳定性和运行效率的核心问题。一个微小的非对齐指针转换，在有 MMU 的操作系统上可能只带来轻微的性能损失，但在嵌入式 MCU 上却可能直接导致系统触发硬件异常（HardFault）而挂起崩溃。

## 嵌入式存储介质与总线架构

在典型的微控制器（以 ARM Cortex-M 系列为例）中，系统存储介质通常分为两大类，它们在物理特性、访问速度和总线连接上各有不同：

### 1. 非易失性存储器（Flash Memory / ROM）
* **物理特性：** 掉电后数据不丢失。虽然读取速度快（通常为几十纳秒），但相比 CPU 核心的时钟周期，在高频运行（如 100MHz 以上）时通常需要配置等待周期（Wait States），或通过 Flash 缓冲/加速器（如 ST 的 ART Accelerator）来缓解延迟。写入和擦除操作非常慢，且需要特定的外设寄存器操作序列。
* **主要用途：** 存放固件代码（指令序列）、常量数据（`.rodata`）、中断向量表以及可读写全局变量的初始化数据镜像（LMA，加载内存地址）。

### 2. 易失性随机存取存储器（SRAM）
* **物理特性：** 读写速度极快，通常可以实现零等待周期（Zero-Wait State）访问，且无擦写寿命限制。但是掉电后数据会完全丢失。
* **主要用途：** 存放运行时的动态变量、堆栈（Stack）空间、动态分配的堆（Heap）空间，以及从 Flash 复制过来的可读写全局/静态变量（`.data`）。

## Cortex-M 物理内存映射拓扑

ARM Cortex-M 采用统一编址的哈佛架构。虽然内部指令总线和数据总线是分开的（以便同时进行取指和数据读写），但在系统地址空间层面，它们被整合到了同一个 4GB 的平面地址空间中。其标准的物理地址空间划分如下：

```
+-------------------------------------------------------------+ 0xFFFFFFFF
|  Private Peripheral Bus (PPB核心外设: NVIC, SysTick, MPU)   |
+-------------------------------------------------------------+ 0xE0000000
|  External Device (外部设备寄存器)                           |
+-------------------------------------------------------------+ 0xA0000000
|  External RAM (外部扩展内存: SDRAM, SRAM, PSRAM)            |
+-------------------------------------------------------------+ 0x60000000
|  Peripheral 区 (片内外设寄存器: GPIO, USART, SPI, DMA)      |
+-------------------------------------------------------------+ 0x40000000
|  SRAM 区 (内部数据/堆/栈)                                   |
+-------------------------------------------------------------+ 0x20000000
|  Code 区 (内部 Flash / 中断向量表)                          |
+-------------------------------------------------------------+ 0x00000000
```

在底层，处理器通过不同的总线接口来访问这些物理区域：
* **I-Code 总线：** 基于 AHB-Lite 协议，专门用于从 `0x00000000 - 0x1FFFFFFF` 的 Code 区域获取指令。
* **D-Code 总线：** 基于 AHB-Lite 协议，专门用于从 `0x00000000 - 0x1FFFFFFF` 的 Code 区域获取字级别的数据（例如常量表格 `.rodata`）。
* **System 总线：** 用于访问 SRAM 区、片内外设寄存器、外部存储区等 `0x20000000` 以上的全部空间。
* **PPB 总线：** 专用的 APB 总线，用于连接内核核心外设（如 NVIC 中断控制器、MPU 内存保护单元、SCB 系统控制块）。

通过多总线并行设计，Cortex-M 能够在从 Flash 取指的同时访问 SRAM 中的数据，从而极大提升了流水线的执行效率。

## 本书学习目标与章节规划

本书专为嵌入式系统工程师与底层系统程序员编写，旨在从**链接脚本、汇编启动代码、编译器属性、底层总线行为以及硬件 Fault 异常分析**等多个维度，系统剖析 C 语言在嵌入式环境下的内存行为。

通过阅读本书，您将掌握以下核心能力：

### 第一部分：嵌入式内存布局
* **[内存布局与物理划分](layouts/README.md)**：整体概览 MCU 物理内存空间的编址逻辑与核心段的划分理念。
* **[第一章：RAM 与 Flash 物理分区及数据段分配](layouts/ram-flash-sections.md)**：
  - 深入剖析 `.text`、`.rodata`、`.data`、`.bss`、Stack（栈）以及 Heap（堆）在 Flash 和 SRAM 中的物理分布与生存期。
  - 理解启动代码（Startup Code）如何利用链接器符号（Linker-defined Symbols）将 `.data` 段从 Flash 拷贝至 SRAM，并将 `.bss` 段清零。
  - 解读 GCC 链接脚本（Linker Script）的语法与段重映射策略（LMA vs. VMA）。

### 第二部分：字节对齐与总线访问约束
* **[字节对齐原理](alignment/README.md)**：整体概览处理器为什么需要对齐访问以及结构体内存对齐的基本规则。
* **[第二章：结构体字节对齐与内存填充原理](alignment/memory-alignment.md)**：
  - 掌握硬件层面的“自然对齐”要求及其背后的总线带宽优化逻辑。
  - 剖析结构体对齐规则与编译器引入的填充字节（Padding）计算。
  - 熟练运用 GCC 的 `__attribute__((packed))` 与 `__attribute__((aligned(n)))`，并分析紧凑排布带来的空间优势与性能、安全代价。
* **[第三章：非对齐内存访问限制与总线异常分析](alignment/bus-faults.md)**：
  - 解析为什么某些 Cortex-M 内核（如 Cortex-M0）不支持非对齐访问，而其他内核（如 Cortex-M3/M4/M7）在特定总线或特定配置下会触发硬件异常。
  - 深入分析 CCR（Configuration and Control Register）寄存器中的 `UNALIGN_TRP` 位配置。
  - 学习如何编写生产级 HardFault/UsageFault 异常处理函数，通过栈帧指针（PSP/MSP）解码发生非对齐异常的精确指令地址（PC）以及目标内存地址，实现快速定位与在线诊断。
