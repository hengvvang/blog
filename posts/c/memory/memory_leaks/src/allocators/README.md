# 第一部分：内存分配机制与安全陷阱

在计算机系统结构中，动态堆内存分配是让程序能够动态适应运行时未知大小数据的核心机制。与生命周期由编译器和函数调用栈帧管理的静态或栈内存不同，堆内存（Heap）为软件架构提供了极高的灵活性，但这种灵活性是以将内存生命周期管理完全交付给程序员为代价的。

本部分将深入探讨动态内存的底层工作机制与高危的安全漏洞隐患。

---

## 核心主题与学习目标

在这一部分中，我们将重点攻克以下两个核心维度：

### 1. [堆内存布局与分配器实现原理](dynamic-allocation.md)
*   **虚拟内存视图**：剖析进程虚拟地址空间中堆区（Heap）的具体位置、生长方向（低地址向高地址）以及与代码段、数据段、内核空间的相对布局。
*   **系统调用与内核交互**：拆解 `malloc`/`free` 底层的 `brk`/`sbrk` 与 `mmap`/`munmap` 机制，理解用户态分配器与操作系统内核如何协同管理物理页。
*   **分配器元数据管理**：以 glibc `ptmalloc` 为参考，揭秘堆块（Chunk）的物理结构（包含 `prev_size`、`size` 及 `A/M/P` 状态标志位）与空闲链表（Bins，如 Fastbins、Unsorted Bin、Smallbins、Largebins、Tcache）的运作机理。
*   **自定义分配器实战**：通过手写一个具备 First-Fit（首次适应）算法、8 字节对齐、块分裂（Split）与相邻块合并（Coalescing）功能的自定义分配器，彻底将理论落地。

### 2. [常见内存泄漏场景与安全陷阱](memory-leaks-traps.md)
*   **内存泄漏（Leaks）的物理图景**：复现异常分支中的提前返回、指针覆盖与悬挂指针、多级结构体“浅释放”导致的泄漏。
*   **运行时安全杀手**：深入剖析 Use-After-Free (UAF，释放后使用) 带来的读污染与控制流劫持，Double Free (双重释放) 对分配器空闲链表（Fastbin Dup）的破环机理，野指针（Wild Pointer）及悬挂指针（Dangling Pointer）的区别。
*   **堆溢出与溢出漏洞**：探讨 Off-by-One 差一错误如何损毁相邻堆块头部，以及整数乘法溢出（Integer Overflow in Sizing）如何绕过内存校验导致严重的堆溢出漏洞。

## 堆内存管理的核心安全守则

为确保动态内存分配在高性能系统中的稳定性与安全性，必须严格遵守以下三条“黄金法则”：

1.  **配对性原则 (Symmetry Rule)**：任何通过 `malloc`、`calloc` 或 `realloc` 分配的内存，在所有的控制流退出路径（包括正常返回、异常退出、条件分支）中，必须有且仅有一次对应的 `free` 释放。
2.  **置空与边界保护原则 (Nullification & Bounds Protection)**：指针被 `free` 后必须立即置为 `NULL`，防止悬挂指针的使用与 Double Free 的发生；在计算分配大小时，必须显式进行乘法/加法溢出检测。
3.  **所有权与生命周期明确性 (Ownership & Lifetime Clarity)**：对于跨模块、多线程共享的数据结构，必须定义明确的内存所有权（谁分配谁释放，或者引入引用计数与清理回调函数），避免浅拷贝和职责混乱。

通过本部分的学习，你将建立起从微观汇编与寄存器地址到宏观软件设计的内存安全防护意识，为后续利用动态监测工具进行定位排查打下坚实的物理基础。
