Stack Memory & Overflow Defense

栈机制概述

在现代计算机体系结构中，函数的执行和状态管理依赖于一个核心的数据结构——函数调用栈（Function Call Stack）。本部分将深入探讨计算机底层是如何利用物理内存与处理器寄存器来构建、维护并销毁函数执行上下文的。

1. 什么是函数调用栈帧？

当程序调用一个函数时，系统必须在内存中开辟一块连续的区域来保存该函数的运行状态。这块区域被称为栈帧（Stack Frame）。栈帧是面向函数调用的私有内存空间，它主要存放以下内容：

  • 输入参数（Parameters）：调用者传递给被调用函数的数据。
  • 返回地址（Return Address）：当前函数执行完毕后，CPU 应跳转回去继续执行的指令位置。
  • 前栈帧指针（Saved Frame Pointer）：用于指向上一个函数栈帧基地址的控制信息，维系着栈帧的调用链关系。
  • 局部变量（Local Variables）：在函数体内声明的非静态变量，其生命周期与栈帧的存续期完全一致。
  • 保存的寄存器（Callee-saved Registers）：在函数执行过程中需要被临时借用，但退出时必须恢复原值的 CPU 寄存器。

2. 寄存器的物理角色

在硬件层面，CPU 通过一系列专用寄存器来追踪和控制栈帧的状态：

  • 栈指针寄存器（SP / Stack Pointer）：指向当前栈帧的顶部（物理内存中地址最低的位置）。它会随着数据的压栈（push）与出栈（pop）而动态改变。
  • 帧指针/基址指针寄存器（FP / Frame Pointer，在 x86_64 中为 RBP）：指向当前栈帧的基准位置（通常紧随返回地址与保存的父帧指针之后）。由于它的值在函数执行期间保持不变，因此编译器可以通过 FP - 偏移量 的固定基址寻址方式来稳定地读写局部变量和参数。
  • 程序计数器（PC / Program Counter，在 x86_64 中为 RIP）：指向 CPU 当前即将执行的指令物理地址。
  • 链接寄存器（LR / Link Register，在 ARM 架构中）：专门用于在执行跳转指令时暂存返回地址，用以避免频繁的内存栈写入。

3. 内存栈的生长与寻址布局

内存栈在虚拟内存空间中采取**向下生长（Downwards Growth）**的策略，即：

  1. 栈底（Stack Base）处于高地址。
  2. 随着函数调用的深入，栈指针 SP 向低地址方向延伸。
  3. 退出函数时，栈指针 SP 向高地址方向回退，释放空间。

虽然栈本身是从高地址向低地址收缩与生长的，但栈帧内部局部缓冲区的写入和读取依然遵循从低地址向高地址的常规数组索引方式。这种生长方向与写入方向的对立，恰恰是后文将要详细剖析的栈溢出安全漏洞的物理导火索。
